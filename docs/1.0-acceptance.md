# VelarScript 1.0 Internal Acceptance Matrix

Status: internal engineering and public-source gates complete; external preview and release evidence pending

This matrix records the evidence available before VelarScript is exposed to
independent users. It closes the repository-owned 1.0 audit, but it is not a
production-ready or release claim. Apache-2.0 now covers the workspace and all
four packed toolchain packages. The attributable development source is now on the
authorized public remote in draft PR #1, with push and pull-request CI passing.
A production claim additionally requires reviewed and merged stable
versioned source, an exact tag, a live
preview, independent application use, compatibility feedback, and an audited
release candidate.

## Requirement-to-evidence matrix

| --- | --- | --- |

Signature labels distinguish omission (`= default`) from nullable input (`?`). A deterministic malformed-input corpus exercises compile, inspect, and format APIs without allowing internal exceptions to escape. The language charter records the accepted surface. | Passing internally |
| Source modules and JavaScript interop preserve checked identity | Cross-module source packages, dynamic `.vel` imports, JavaScript npm packages, bounded `.d.ts` graphs, native classes, aliases, inheritance, and nominal identities run through compiler, package, and LSP tests. | Passing internally |
| Web applications own failures and cleanup | Release Studio exercises route, event, render, resource, action, HTTP cancellation, logging, and recovery paths. Hostile HTTP, file, realtime, form, route, browser-helper, storage, and IndexedDB values are rejected before unsafe side effects or through their owned asynchronous channel. The development server contains an unexpected watched rebuild failure, retains the last good application, reports the failure through status/SSE, recovers on the next edit, and converges after a 64-write burst. | Passing internally |
| JSX, reactivity, components, and browser output are portable | Development and verified CSP production suites pass Chromium, Firefox, and WebKit. ## Authoritative gates

Run from the VelarScript repository:

```text
npm run check
npm test
npm run test:packages
npm run test:browser
npm run release:rehearse
npm run release:verify -- release/rehearsal
```

Run from the independent Workbench repository against the rehearsal manifest:

```text
bun test tests/language-support.test.ts
bun scripts/test/verifyInstalledVelarToolchain.ts <absolute-release-directory>
```

The compiler/CLI gate currently contains 197 tests before the three real Core
application suites. The browser gate separately covers development, verified
CSP production, all three real applications, and a freshly generated project.
Counts are supporting detail; the commands and named contracts above are the
acceptance authority.

## Remaining external gate

The following work is intentionally not inferred from green local tests:

1. review and merge the public development-source PR without weakening its gates;
2. explicitly authorize and deploy a hosted preview from an exact source identity;
3. verify the live deployment from another network and browser context;
4. collect independent application feedback and convert every release-blocking
   compatibility finding into a retained test;
5. after that feedback, choose the stable version, create the exact version tag, and audit the
   clean release candidate;
6. explicitly authorize npm publication.

Until those items have evidence, describe VelarScript as **internally accepted
for external preview**, not production-ready.
