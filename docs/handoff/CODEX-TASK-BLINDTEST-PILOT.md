# Codex 任务书 —— 盲测试点（路线图第三阶段的第一次实弹）

你是**盲测对象**。目的：检验「AI 只凭内置简报 + 编译器诊断能否写出符合典章的
Vel 代码」—— 这是本语言的核心 KPI。**你的挣扎本身就是产出**。

## 盲测纪律（最重要的规则）

- **只允许两个信息源**：① `velar skill` 命令的输出（语言简报）；② 编译器/
  工具的诊断消息。
- **禁止**阅读：docs/ 下任何文档、packages/ 下任何源码、tests/、examples/、
  HANDOFF、charter。禁止上网查。你对 Vel 的全部知识必须来自简报与报错。
- 撞墙时**先按诊断说的做**；诊断没教明白就记录下来（这是最有价值的发现），
  然后允许合理猜测继续。

## 准备

在**仓库之外**新建目录（例如 `~/velar-blind-pilot/`）。用仓库构建的 CLI：
`node <repo>/packages/cli/src/cli.ts`（或按 README 装法）。先跑 `velar skill`
把简报存一份，此后只看它。

## 三个任务（递增复杂度，各自独立目录）

1. **task1-cli**：命令行小工具 —— 读一个 JSON 文件（含一个订单列表：id、
   金额、状态枚举），输出按状态分组的金额汇总与最大三笔订单。要求有测试。
2. **task2-web**：Web 小应用 —— 一个待办面板：输入框添加、点击切换完成、
   按状态过滤、显示计数。要求用组件的四种 cell 中至少三种，有一个浏览器测试。
3. **task3-domain**：领域建模 —— 一个小型库存系统：商品类（含校验）、入库/
   出库操作（错误处理）、库存报表（排序与聚合）、外部 JSON 数据校验入口。
   要求测试覆盖错误路径。

每个任务完成标准：`velar check` 零诊断、`velar test` 全绿、代码是你认为
「简报教你的那种写法」。

## 记录（产出的核心，边做边记）

对每个任务写 `NOTES.md`：

1. **撞到的每一条诊断**：原样消息 + 你按它改了什么 + 它有没有一次教会你
2. **简报没覆盖的问题**：你想做 X，简报没说，你猜了 Y —— 列出每一处猜测
3. **写错但没被抓住的地方**：如果有编译通过但行为不对的时刻，详细记录
4. **最想要但找不到的能力**：功能/方法/语法层面
5. 每个任务的**总耗时与返工次数**

## 交付

三个项目目录 + 各自 NOTES.md + 一份总结 `SUMMARY.md`（最痛的三处、最顺的
三处、你会给这门语言的一句话评价）。**不要**修改 Vel 仓库的任何文件。
