## 第 37 条 —— 可选链恢复 JS 整尾短路（本轮最重，归批次 F）

### 现状（实测）

```
type Inner:
    deep: string            // deep 不是可选的

b.inner?.deep.upper()       // 被拒：VEL4001 Use optional access '?.' for string?
b.inner?.deep?.upper()      // 被迫给非可选字段写 ?.  —— 语义谎言
```

JS 亲代的可选链是**整尾短路**：`?.` 之后的尾部不会在 null 上执行，
`b.inner?.deep.upper()` 在 JS 合法且安全。Vel 现把上游可空性摊平成 `string?`
再要求下一链节自己处理 —— 强迫给永不为空的字段写 `?.`，与 JS 肌肉记忆分叉，
与发射目标的运行时语义分叉，且让 `?.` 失去信息价值。

### 目标语义

- 一条成员/下标/调用链中出现 `?.` 后，**后续非可选链节写普通 `.`**；整链结果
  类型为可选。真正可选的链节照旧写 `?.`。法律一句：**`?.` 出现的位置 = 真实
  的可空位置**。
- 运行时语义即 JS 链尾短路（发射可直接用原生 `?.` 链）；既有的
  undefined→null 归一化契约不变（charter §5「Every optional access result
  normalizes …」维持）。
- 链内事实沿用 charter 既有句：过了 `?.` 的守卫接收者在其后链节中已知在场。
- 迁移：全仓被迫多写的 `?.`（非可选链节上的）收走；真可选链节（如
  `findMatch(...)?.groups?.[0]` 的 groups）不受影响。旧拼写（多余 `?.`）保持
  合法还是给指引？—— **给指引**（一个明显拼写：`deep` 非可选就不许写 `deep?.`，
  否则读者被误导），消息教删除多余的 `?`。
- charter §5「Optional access is explicit at each optional continuation」改写
  为链尾短路语义的准确表述。
- 回归：null 短路整尾（执行级）、在场路径全链执行、混合链（`a?.b.c?.d`，
  b 非可选 c 可选）、可选调用/下标在链尾、`??` 收尾、多余 `?.` 得到指引。

## 第 38 条 —— 原生属性已知表检查（归批次 I）

### 现状（实测）

`<div clas="x">` 静默通过 —— `class`/`href` 笔误家族全部放行（属性**值**类型
检查存在，属性**名**存在性检查缺失）。

### 目标语义（用户选定选项 a）

- 原生元素属性名必须命中：HTML/SVG 已知属性表（属性值类型检查已在用的那张表
  为基础，补全存在性维度）∪ `data-*` ∪ `aria-*` ∪ 既有指令族（`on:`/`bind:`/
  `look:`/`style:`/`unsafe:`/`key`/`ref`）。
- 未知名 → 定向诊断，含最近已知名建议（`clas` → `Did you mean 'class'?`，
  沿用语言服务器既有的最近拼写机制若存在）与 `data-*` 出路。
- 自定义元素（含连字符的标签名）若语言暂不支持则维持现状；若支持，其属性
  免检并成文。表的维护成本诚实标注：新属性随浏览器演进按需补表，`data-*`
  是永远的出路。
- 回归：已知属性通过、`clas` 报错带建议、`data-task`/`aria-label` 通过、
  SVG 属性通过（api-dashboard 的 SVG 示例是现成语料）。

## 第 39 条 —— 字符串外的双向控制字符报错（归批次 E）

### 现状（实测，Trojan Source 探针）

- 字符串字面量内 bidi 控制符：**合法**（正确 —— 阿拉伯语等真实内容需要）。
- 标识符内零宽字符：**已拒**（VEL1001，正确）。
- **注释内 RLO（U+202E）：静默通过** —— 审读欺骗的主要载体（Rust/GCC 为此加
  警告，GitHub 标黄）。Vel 的 owner 只有「读代码」这一层防御，宗旨「人来读」
  使审读欺骗成为命门级攻击面；且诊断系统无警告级别，故直接报错。

### 目标语义

- 字符串/布局字符串字面量**以外**的位置（注释、代码、标识符间）出现 bidi
  控制字符（U+202A-202E、U+2066-2069）→ 词法错误，消息说明审读欺骗风险并
  指引「把双向文本放进字符串字面量」。
- 字符串内维持合法；f-string 插值表达式属代码位 → 拒绝。
- 回归：注释 RLO 报错、字符串内 RLO 合法、插值内 RLO 报错、正常 RTL 文本内容
  不受影响（执行级输出字节不变）。

## 第 40 条 —— 块注释加入语言、指引两连、两句文档

1. **新增 `/* */` 块注释**（用户 2026-08-12 裁决，推翻「只给指引」的原建议）。
   JS 亲代肌肉记忆；设计三点：
   - **嵌套**：`/* */` 可嵌套（Rust 先例）。理由：注释掉含块注释的代码永远
     可行；与 JS 的分叉只发生在「JS 下提前闭合导致语法错误」的形态上 ——
     响亮分叉、无静默分叉。
   - **行纪律（缩进语言特有）**：行内形态必须**同行闭合**
     （`const a = /* note */ 1`）；跨行形态必须**独占整行**（开闭行除缩进外
     无其他内容）。禁止「语句中间开、下一行闭」—— 否则块注释成为第二种语句
     续行机制，破坏「语句止于行尾」。违反给定向诊断。
   - **不加 `/** */` 文档语义**：`///` 仍是唯一文档注释拼写；`/**` 开头只是
     普通块注释首字符为 `*`，无特殊含义（skill 教 `///`）。
   - 第 39 条的 bidi 规则覆盖块注释内部（注释即字符串外位置）。
   - 格式化器保留块注释并有幂等回归；charter §2 成文。归批次 E。
2. **`a, b = b, a`**（Python 换位）→ 现吃通用 VEL2032。定向变体：赋值目标后
   跟逗号时教 `swap with a temporary binding; tuple assignment is not part of
   VelarScript`。归批次 F。
3. **`x = y = 5`**（JS 链式赋值）→ 同上通用 VEL2032。定向变体：教
   `assign one binding per statement`。归批次 F。
4. **文档两句**（归批次 C，并入 D29 第 15 条的 `%` 成文）：负数取模取 JS 语义
   （`-7 % 3 == -1`；Python 给 2）。用户裁决并立法（2026-08-12 原话）：
   「**本质上是运行在 js 上的，所以行为优先 js，只不过写法更像 py ——
   父亲和母亲的区别**」。角色分配经用户复核定为：**JS 是母亲**（程序在母体内
   运行 —— 运行时即子宫，行为随母），**Python 是父亲**（姓随父 —— 外在拼写
   名分随父姓）。该法律通用于一切亲代分叉：语义问题问母亲（JS），拼写问题
   随父亲（Py），母亲的行为是陷阱时才移除（charter 规则 1+2 边界）。
   追认既有裁决：`==` 严格、引用相等、IEEE 浮点、每调用默认参数、闭包按迭代
   捕获（行为侧）；缩进块、and/or/not、def、f-string（拼写侧）。
   （原拟的「NaN 分裂一句成文」被第 41 条取代 —— 分裂本身被修掉。）

## 第 41 条 —— NaN 语义统一：SameValueZero + 谓词三件套 + 聚合围栏（归批次 A）

用户 2026-08-12 裁定 NaN 分裂是需要处理的缺陷并批准本方案。定性：这是母亲
（JS）自己的历史遗留陷阱 —— JS 新 API（`includes`、Map、Set）已全部改用
SameValueZero，只有旧 `===` 留着 IEEE 坑，造成 `NaN === NaN` 假而
`Set.has(NaN)` 真的精神分裂。按父亲/母亲法律的陷阱豁免（「父亲的行为是陷阱
时才移除」），Vel 一步到位。

### 目标语义

1. **`==` / `!=` 采用 SameValueZero**（唯一分歧：`NaN == NaN` → `true`）。
   自反性恢复（`x == x` 永真）；与 Set/Map 键、`List.has/index/count/remove`
   说同一种话。±0 行为不变（`-0 == 0` 仍真，与 `===` 一致）。
   发射：`a === b || (a !== a && b !== b)` 短路形态；**类型驱动消除** ——
   操作数静态类型不含 number/unknown/any 时发射裸 `===`（D34-P4 检查消除的
   第一个实战案例）。集合成员操作统一核对为 SameValueZero（`List.has(NaN)`
   现状若为 `===` 恒假，与 `Set.has(NaN)` 真即是今日分裂的另一处，一并修）。
2. **数字谓词三件套**：`isNaN()`、`isFinite()` 加入数字方法表（与 D29 10b 的
   `isInteger()` 同批同表）。统一后 JS 的 `x !== x` 黑话失效，`x.isNaN()`
   是唯一拼写。
3. **聚合围栏**：`sum()` / `min()` / `max()` / `sorted()`（数值默认序与
   `by=` 数值键）遇 NaN 元素抛定向错误（如 `NaN has no ordering`）——
   NaN 使排序退化为乱序、聚合中毒；有界辅助器本就逐元素扫描，加 `x !== x`
   近乎免费。错误消息指引 `filter(x => not x.isNaN())` 或修上游。
4. **明确不做（防复议）**：不做受检算术（`0/0` 抛错需给全部算术热路径加守卫，
   税不可接受；NaN 已在等式/聚合/谓词三处变响）；比较运算符 `<`/`>` 保持
   IEEE 父亲行为（`NaN < 5` 恒假，文档一句，围栏已拦住其作恶主场）；
   `number()` 转换已返回 `number?` 而非 NaN —— 既有正确设计，成文一句。
5. **文档**：charter §4 等式段补 SameValueZero；父母法律的陷阱豁免案例
   清单 = `===`→`==`（强制严格）与 NaN 统一，两案并列。
6. 回归：`NaN == NaN` 真、`x == x` 永真（执行级）；string/enum/记录等式发射
   为裸 `===`（发射形态断言）；`List.has(NaN)` 与 `Set.has(NaN)` 一致；
   四个聚合的 NaN 围栏各自命中且消息含出路；`isNaN`/`isFinite` 六输入断言；
   ±0 全家行为不变。
