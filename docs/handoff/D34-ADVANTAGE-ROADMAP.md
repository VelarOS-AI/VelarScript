# D34 — 优势与高级功能路线图（雏形，活文档）

用户于 2026-08-12 批准立档。**本文是路线图雏形，不是实施规格**：方向会随证据
演变（用户原话点名 WASM 扩展之类的可能性），每条车道启动前需要单独的可执行
规格与批准。唯一从落笔起就生效的是「法律」节。

定位前提：Vel 是**语言框架**三位一体 —— 既是语言、又是框架、语言内核还可
自定义扩展（W-126 的目标中立扩展协议：AST 节点、类型族、可赋性、成员、语义
类别、编辑器呈现、格式化、分析、发射、模块、运行时依赖）。优势车道全部长在
这个别人抄不走的位置上。

**阶段门**：所有车道排在三阶段路线（评审语法 → 找漏洞 → skill 盲写闭环）
**之后**启动。地基未验完不开新战线。

---

## 法律（从落笔起生效，不随雏形演变）

1. **扩展加词汇，永不加同义词。** 扩展只能为新领域添加语法词汇（如 Web 的
   `component`/`look`/单位字面量 —— Core 没有的概念），永远不能为已有概念添加
   替代拼写。违反即在语言层面复活「千人千面」，直接对抗使命。
2. **`velar skill` 聚合扩展。** 每个扩展包自带 skill 章节；`velar skill` 输出 =
   核心典章 + 已安装扩展各自章节。语言无论怎么扩展，AI 看到的永远是当前项目
   完整方言的说明书。可扩展性与 AI 可写性由此共生。（实施随 D33 批次 J。）
3. **宣传口径锁定「框架级性能」**（渲染/响应/启动/体积），永不宣称「语言级
   性能」—— 产物就是 JS，热循环同速。每个对外数字必须 CI 产出、可复现。
4. **边界不动**：Agent 编排不属于 `@velarscript/*`（W-52 裁决，归 VelarOS
   产品层）；语言侧 AI 相关扩展至多是 prompt 模板类语言构造。

## 一、已成事实、只差包装与测量（零语言开发，随官网任务走）

| 项 | 现状证据 | 包装动作 |
|---|---|---|
| 属性级深层响应、无 VDOM、无 memo/batch API | D26；Lite S4 每 chunk 10 构建/7 扫描 → 0/0 | 官网叙事 + 基准 |
| 类型即运行时验证器（`Type.parse` 零双份 schema） | 语言现状 | 官网对比 TS+Zod |
| Look 静态提取（CSS-in-JS 表达力、零运行时注入） | 语言现状 | 官网对比 styled-components |

| 可读产物反锁定 | D33 弹射门禁（批次 J） | 官网承诺 + 门禁链接 |

## 二、性能与体积车道（语言层独有）

结构性前提：allowlist 语法没有动态逃逸口（无 eval、无动态属性访问、无原型
改写）→ 可达性是**可判定事实**，不是打包器的启发式猜测。

- **P1 体积预算门禁化**（小活、大感知，建议首发）：`velar.json` 声明
  `budget`，超出即构建失败，报告分项字节。Desktop 已有同款（10 MiB 硬预算 +
  分项清单），搬到 Web。验收：预算超限的最小复现构建失败 + 报告可读。
- **P2 路由级自动分包**：`route()` 表是静态声明 → 自动 per-route 分包 +
  预加载，零配置（`lazy()` 已有，自动化）。验收：多路由示例首屏 JS 只含
  首路由。
- **P3 完美死代码消除**：逐 helper 按需发射推到极致（W-102~104 已开头）。
  验收：hello-world 基线字节数入 CI，逐版本只降不升。
- **P4 检查消除优化**（大活、最独家）：analyzer 流事实证明后删除运行时检查
  （`for x in list` 体内免索引检查、已验证边界内的读免守卫）——「安全不减速」：
  安全是承诺，速度把成本收回来。TS 做不到（不插守卫）、裸 JS 做不到（无事实）。
  验收：基准套件上检查开销占比数字化并下降；语义零变化（对抗搜捕复跑）。
- **P5 公开基准**：进 js-framework-benchmark（krausest）；`tests/performance.test.ts`
  扩为基准套件。验收：公开榜单条目 + 官网对照表全部 CI 产出。

## 三、高级功能车道（三位一体独有）

- **A1 运行时也可读：零配置时间旅行 devtools**（最高推荐，与宗旨严丝合缝）：
  编译器拥有每个 state 单元与每处突变语法（属性级追踪已在记录依赖）+ 源码
  span → 状态时间线：谁、哪一行、把什么改成什么，可回放。「人来读」延伸到
  运行时 —— 非程序员 owner 看时间线即可理解 app 行为。
- **A2 端到端类型的服务端函数**：serve + web 同一模块图，客户端调服务端函数
  参数/返回值编译期检查、Type 验证器自动守边界，无 codegen 无双份 schema。
  对标 tRPC/RSC，但在语言层原生。
- **A3 能力安全作为语言表面**：Desktop 的 permission-scoped 能力 + manifest
  硬预算搬到 Web —— velar.json 声明允许的 hosts/权限，构建期生成 CSP 并验证。
  叙事：「这个 app 能碰什么，manifest 说了算、编译器证明」；owner 不懂代码
  但看得懂权限清单。
- **A4 确定性测试即默认**：框架拥有时间/DOM/网络全部接缝（velar/web-test
  确定性宿主已存在），把「无 flaky 测试」包装为承诺。开发量小。
- **A5 领域语言即 npm 包**：`velar/game`（用户初心，W-126 为其铺路）、图表、
  表单 —— 带完整检查/编辑器/格式化的真语法，非字符串伪 DSL。维持 HANDOFF
  既有裁决：**等外部用户证据再开**；「协议已 ready」本身即官网叙事。

## 四、留门项（远期，可能性而非承诺）

- **WASM 扩展**（用户点名的例子）：Core 永远保持 JS 运行时模型（charter
  规则 1 不动摇），但扩展协议正是未来 WASM 能力的正确居所 —— 例如受检的
  extern-WASM 模块边界，或把有界数值核编译到 WASM 的计算扩展。**留门的含义**：
  今天不设计、不承诺，但任何车道的实施不得堵死「能力经由扩展协议进入、不污染
  Core」这条路。同类留门：多线程/Worker 能力包。
- 稳定通道（长生命周期产品）：由外部证据触发，见 D33 第 34 条兼容性政策。

## 五、优先序（当前判断，允许被证据推翻）

**A1 时间线 devtools → P1 体积门禁 → A2 端到端类型 → A3 能力安全 → P2 自动
分包 → P3 完美消除 → P4 检查消除 → A5 领域扩展**；P5 基准与一（包装）随官网
任务并行。A4 视测试文档现状可随时插入。
