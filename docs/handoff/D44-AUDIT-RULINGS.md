## 第 70 条 —— 记录验证拒绝非纯对象（CLS-D6，正确性最高优先）

### 现状

```
type Point:
    x: number

class P:
    const x: number = 1
    def read() -> number: return self.x

const raw: unknown = P()
const point = Point.parse(raw)   // 成功；Point.is(P()) 为 true
point.x = 99                     // 经记录视图写
print(instance.read())           // 99 —— 类的 const 字段被写穿
```

**根因**：静态上类是标称的（`const p: Point = P()` 被拒），运行时验证器是
**结构**的 —— 它检查「自有可枚举数据字段」，而类实例在构造器里赋的字段正是
自有可枚举数据属性。验证器放进来的恰是静态系统禁止的东西；返回的记录视图
**别名活实例**，而 `const` 仅编译期、运行时零保护。

**危害**：`unknown → 验证 → 使用` 是官方宿主数据通路。类实例能走这条路，
就意味着**凡经过验证的代码路径里 `const` 字段都不是 const**。

### 目标语义

- **记录运行时验证（`Type.is` / `Type.parse`，含嵌套记录字段）拒绝原型不是
  纯对象原型的值**。类实例、`Error` 实例、宿主对象一律不再满足记录契约。
- **跨 realm 必须正确**：判定不可直接比 `=== Object.prototype`。沿用集合面
  已有的跨 realm 结构化 brand 方案（charter 已成文「原生 Map/Set brand 经内部
  槽检查，故其他 realm 的合法值可用」），对纯对象采同等强度的判定：原型为
  `null`，或原型自身无原型（即某 realm 的 `Object.prototype`）。
- **诊断/错误消息**教清楚：`ValidationError` 说明「记录契约要求纯数据对象；
  类实例请显式投影出记录（`{x: instance.x}`）」。
- charter §12 的「Every runtime `Type.is`/`Type.parse` record check requires its
  non-optional fields to be present own enumerable data properties」一段**追加
  纯对象要求**；§10 或 §5 补一句「类 `const` 字段的保护是编译期的，验证器不会
  为它提供运行时保护 —— 因为类实例根本不满足记录契约」。
- **顺带解决 CLS-C1 的后果 2**：`type Runner: run: () -> null` 的
  `Runner.is(P())` 从此为 false，与 §12「继承字段与访问器不满足记录契约」
  一致，**且不再取决于方法降级方式**（见第 74 条）。
- 迁移：门禁为准。任何依赖「验证类实例成记录」的代码正是要坏掉的。
- 回归：类实例被 `is`/`parse` 拒绝（含嵌套字段位）、`Error` 实例被拒、
  JSON 解析结果通过、跨 realm 纯对象通过（用 realm 双份的执行级测试）、
  `const` 字段无法再被写穿（执行级）。

## 第 71 条 —— 赋值建立收窄事实（FLW-N1，人体工学最高收益）

### 现状

```
const x: string? = "a"
print(x.upper())        // 报错：Use optional access '?.' for string?
```

赋值把收窄类型重置回声明类型。作废与建立**共用一条代码路径** —— 作废是系统
健全的基础，当初只做了作废，从未加建立。

### 目标语义

赋值（含带初始化器的声明）**为被赋位置建立「右侧表达式类型」这一事实**。
这在绑定上是最可靠的事实：赋值之后该位置的值就是右侧的类型，无任何别名疑虑。
标准流类型（TS 同款）。

**完整情形表**：

| 形态 | 建立的事实 |
|---|---|
| `const x: string? = "a"` | `string` |
| `let x: string? = null` 之后 `x = "a"` | `string` |
| `x = maybeNull()`（右侧仍可空） | `string?`（不收窄，正确） |
| `a.b = "a"`（成员路径） | 为 `a.b` 建立；**但仍先作废其他路径**（别名），顺序是**先作废、再为被写路径建立** |
| `if c: x = "a"` / `else: x = "b"` | 两臂各建立 `string` → 合并后 `string`（审计发现今天缺席的情形） |
| 全部 `match` 分支都赋非空 / try-catch 两臂都赋 | 同上，合并后有事实 |
| `x += 1` | 已保持事实，行为不变 |
| 解构声明 | 按各绑定的初始化器类型建立 |

- **实施顺序是本条的关键风险**：成员赋值必须「先 invalidate、后 establish」，
  否则新建立的事实会被自己的作废清掉。
- charter §5 追加「赋值建立事实」段落 —— 现文只说 `=` **作废**，从未说是否
  **建立**，这个沉默就是缺口本身。
- 回归：情形表逐行；`x = maybeNull()` **不**收窄的负面断言；成员赋值同时
  作废别名路径又为被写路径建立（同一测试覆盖两半）；合并三形态。

## 第 72 条 —— readonly 只能修饰纯数据（CLS-U5，2026-08-12 用户改稿）

### 修订记录（诚实标注，初稿作废）

本条初稿方案是「readonly 类视图 + `readonly def` 可调用」，依据 Lite 账本 W-75
「resolved upstream as a Core language contract」。**该记录已过时**：
`readonly def`/`readonly get` 后来被移除（用户记忆正确），charter §5 现文明写
「There is no readonly class or readonly executable-member contract」，实测
`readonly def` → VEL2021。初稿建在过时前提上，**作废**。用户随后裁决：
**「能不能让 readonly 只能修饰数据」→ 采纳，本文即该方案。**

### 现状（洞）

```
type Holder:
    item: Scale                  // Scale 是类

def look(h: readonly Holder) -> number:
    h.item.n = 5                 // 通过，且真的改了（实测输出 5）
    return h.item.peek()         // 任意方法也可调
```

readonly 对数据传递，但数据里藏着类成员时保护在该成员处终止。顶层
`readonly Scale` 今天**已被拒**（"'readonly' applies only to data records,
structural objects, List, Set, Map, and Record values"）—— 但检查只做表层。

### 目标语义：把既有检查从表层做到全深度

**规则一句话：`readonly T` 要求 T 的全部可达结构都是纯数据**（记录、结构对象、
List/Set/Map/Record、原始值、枚举、可选、联合）；**任何深度**出现类类型 →
在 readonly **声明处**编译错误。

为什么优于「文档成文洞」（原选项 B）与「访问处拦截」（原选项 A）：B 是把漏洞
写进文档，本方案是**有漏洞的承诺根本不让许下** —— 承诺范围与接受范围重合，
readonly 从此不存在「保护不到的可达位置」。错误报在声明处也早于报在访问处。

- 诊断教两条出路：「Holder 的成员 item: Scale 是类，readonly 只保护数据 ——
  把它建模为数据记录，或去掉 readonly」。
- **补完而非新规则**：顶层拒绝已存在，本条把同一检查做成传递闭包。
- 联合任一成员含类即拒绝；递归记录类型判定须记忆化（环安全）。
- **泛型参数 T 不受限**：裸 T 无任何成员操作（审计实测 `T has no member`），
  不透明性等价于不可变性 —— `readonly List<T>` 保持合法，既有泛型不回归。
- **类作为组件 prop**：**裸类 prop**（`scale: ChartScale`）保持合法，按行为值
  原样传递，charter §15 追加限定句「props 的 readonly 承诺覆盖数据 prop；类
  prop 是行为值，原样传递不受保护」—— 读者看得见它是类。但**藏在记录 prop 里**
  的类与显式 readonly 同规则拒绝：埋在数据里的类是「长得像数据的谎言」，出路
  便宜（把类提升为独立 prop）。W-75 的 ChartScale 形态是裸类 prop，不受影响。
- `unknown`/`any` 成员放行 —— 它们本就是静态承诺终止的边界。但实施者须核实
  「readonly 视图内的 unknown 经 `Type.parse` 后是否别名出可变视图」并呈报
  （若别名，是同族残洞，单独立项）。
- 迁移实测：全仓 `.vel` 仅 12 处 readonly 站点，全在 stdlib javascript.vel，
  修饰的都是纯数据记录 —— **预期破坏面为零**。
- charter §5 改写：删除「传递性在类成员处静默终止」的隐含状态，改为「readonly
  类型的任何深度不得出现类；类是行为值，不进入 readonly 边界」。
- 回归：含类成员的记录被拒（声明处，含嵌套两层与 List<类> 元素位）、联合任一
  含类被拒、`readonly List<T>` 泛型合法、裸类 prop 合法且方法可调、记录 prop
  含类被拒、递归记录类型不死循环、stdlib 的 12 处既有站点不回归。

## 第 73 条 —— 成员写按类型不相交精确作废（FLW-D2）

### 现状

```
if box.value != null:
    other.count = 2              // 写的是完全不同类型的另一个变量
    print(box.value.upper())     // 报错：事实被杀
```

charter §5（518 行）承诺「无关的根保持其事实」，实现对**任何**成员赋值调
`invalidateCurrentMemberNarrowings()` 清空帧内全部成员事实。**这句话与这段
代码不能同时成立。**

### 目标语义（第三条路，不是「改代码 vs 改文档」二选一）

用**类型不相交**判定「这两个根有可能是同一对象吗」：

- 被写路径的根类型与事实的根类型**无交集** → **保留事实**（不相交的类型不可能
  别名，健全）。
- 判定复用**批次 A′ 第 64 条刚建的类型交集谓词** —— 零新机制。
- 残余保守**精确成文**：**同类型**的两个根仍互相作废
  （`box2.value = null` 作废 `box.value` 的事实）—— 健全且很少意外。
- 成本：每次成员写对每条在场事实一次谓词调用，可接受。

charter §5 那句话对常见情形因此成为真的，剩余保守被写清楚（现文的绝对承诺
改为「类型可能别名的根之间互相作废」）。

- 回归：不同记录类型的无关根**保留**事实（审计的原始复现）、同类型两根互相
  作废、别名六形态（审计已确认正确的那批）**不回归**、兄弟字段写仍作废
  （同根即同类型）。

## 第 74 条 —— 类方法走原型 + 引用点绑定（CLS-C1）

### 现状

charter §18 承诺「类降级为 JS 类与原型」，但发射器把每个公开非静态方法
`bind` 到实例（`this.seed = this.seed.bind(this)`）。三个后果：
`print(instance)` 显示方法；带函数字段的记录类型被类实例满足；方法引用
（`const f = a.read`）**只因为该绑定**才能用；每实例每方法一个闭包。

### 目标语义

- **改走原型**（兑现 §18 的承诺，降低内存，检查输出干净）。
- **方法引用在引用点绑定**：`const f = a.read` 发射为「求值一次接收者 + 绑定」。
  **语言已有此先例** —— charter §8 明写「受检值与集合方法是一等的**已绑定**值：
  `const add = tags.add` 保持 `tags` 接收者，接收者表达式在方法值创建时求值
  一次」。类方法采同一规则，属**一致化而非新语义**。
- **优先级说明**：后果 2（记录被类实例满足）由第 70 条**独立解决** ——
  验证器拒绝非纯对象后，`Runner.is(P())` 无论怎么降级都是 false。故本条剩下的
  是内存与整洁，**不再是正确性问题**；但 §18 的措辞无论如何必修。
- 私有方法当前降级为持有箭头的私有**字段**（`#name = (…) => {…}`），
  §18 说「`private` 降级为原生私有成员」—— 一并改为原生私有方法，或把该差异
  成文（实施者按可行性择一并呈报）。
- 回归：方法引用取出后调用正确（执行级，含 `self` 绑定）、原型方法不出现在
  `print` 输出、继承链方法查找正确（第 72 条落地后类不再出现于 readonly 类型内，本条与 readonly 无交互面）、内存形态断言（每实例不再每方法一个闭包 —— 以发射形态断言而非内存测量）。
