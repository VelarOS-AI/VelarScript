# Codex 任务书 —— 盲测第二轮：写 + **改** + 新表面

第一轮盲测（2026-08-13）测的是「从零写」，结论是「语言核心过关、引导故事是短板」
（领域建模 0 返工、Web 14 返工，全因项目激活无处可查）。引导故事已修完。

本轮补两件第一轮没测的事：**① 修改别人写的代码**（使命原话是「AI 写**和改**，
人来读」—— 改从未被测过）；**② 只有实现者用过的新表面**。

## 盲测纪律（与第一轮相同，最重要）

- **只允许两个信息源**：`velar skill` 的输出；编译器/工具的诊断消息。
- **禁止**阅读 docs/、packages/、tests/、examples/ 的源码与文档、HANDOFF、
  charter；禁止上网查。
- 唯一例外：**阶段二**要求你读被修改项目的 `.vel` 源码 —— 那正是「人/AI 读
  别人的 Vel」这件事本身，是被测对象，不是作弊。
- 撞墙先按诊断做；诊断没教明白就记下来（**这是最有价值的产出**）再合理猜测。

## 准备

仓库外新建目录（如 `~/velar-blind-2/`）。用仓库构建的 CLI。先存一份
`velar skill` 输出，此后只看它。

## 阶段一：从零写一个真实规模的应用（不是玩具）

**任务**：一个「阅读清单」Web 应用 —— 添加链接（URL + 标题 + 标签）、按标签
过滤、标记已读、按添加时间或标题排序、数据存到 localStorage、启动时读回并
用 `Type.parse` 校验、错误路径有可见反馈。要求组件拆成至少三个文件、有单元
测试与浏览器测试。

**目的**：规模足以让「模块划分、状态归属、错误处理」真的发生，而不是玩具级的
一个文件。

## 阶段二：改一份你没写过的代码（本轮的核心）

在 `/Users/mac/Documents/VelarScript/examples/production-web` 上做三项修改。
**把项目复制到你的工作目录再改，不要动仓库**。

1. 给它加一个新页面/新组件（自选一个与现有内容自洽的功能）；
2. 找出并修改一处现有行为（例如某个列表的排序规则或过滤条件）；
3. 给你改动的部分补测试。

**记录重点**：读懂别人的 Vel 花了多久？哪些地方**读不懂或读错了**？（读错了
但编译器抓住了 = 语言在兜底；读错了且编译通过 = **最严重的发现**。）

## 阶段三：新表面（只有实现者用过）

写一个小程序自然地用到下面每一项，并记录**你是怎么发现它的**（简报里有？
诊断教的？猜的？）：

- `using` + 一个自定义类的 `@dispose:`
- 带约束的泛型（`<T: Text>` / `Comparable` / `Data` 之一）
- `try` 表达式
- `test "名字":` 块
- `Text.` 与 `Json.` 常驻命名空间（不写 import）
- 反引号字符串装 JSON
- 一个 `catch` 里用 `is` 判别具体错误类（如 `FileNotFoundError`）

## 记录（产出核心）

每阶段一份 `NOTES.md`：

1. **每条撞到的诊断**：原样消息 + 你改了什么 + **是否一步教会**（是/否）
2. **简报没覆盖而你只能猜的每一处**
3. **编译通过但行为不对的时刻**（最高价值，详细写）
4. **阶段二专属**：读别人代码时的困惑点、读错的地方
5. 每阶段耗时与返工轮数

## 交付

三个阶段的产物 + 各自 NOTES.md + 一份 `SUMMARY.md`（最痛三处、最顺三处、
**与第一轮相比 Web 返工数的变化**、一句话评价）。**不要修改 VelarScript 仓库
任何文件**。
