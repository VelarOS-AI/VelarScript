## 第 75 条 —— 类名不是一等值（CLS-U6）

### 现状：半个一等值

`const factory = P` 与 `print(P)` 可用；但 `List<P> = [P]` 被拒（消息还把两种
内部类型用同一显示名对比）、`(() -> P)` 参数位被拒、`[P, Q]` 元素类型成
`P | Q` 后不可调用、经空值检查后间接调用触发 CLS-D5 崩溃。补全需要发明
`Class<P>` 类型家族。

### 裁决：不做一等类值，类名只能直接使用

- **合法位置**（穷尽）：直接调用 `P()`、静态访问 `P.member`、`extends P`、
  类型位置、`is P` / `case P:` 模式、`export {P}`（导出声明）。
- **其余一律拒绝**：起别名、作实参、进集合、作返回值、`print(P)`。
  诊断教一条出路：「类名不是值；直接调用 `P()`，工厂请写箭头 `() => P()`」。
- **先例**：抽象类今天已禁止别名/集合/元素调用 —— 本条把所有类拉齐到同一行为，
  消除「抽象类一套规则、具体类另一套」的不一致。
- extern 类同规则。
- 迁移：全仓扫描类名值用法（预期极少）。
- 回归：五种拒绝位置各一条 + 六种合法位置各一条正面断言 + 箭头工厂执行级。

## 第 76 条 —— override 签名严格不变，成文（CLS-U3）

现状即裁决：覆盖必须与基类签名完全一致（含返回类型 —— `-> number` 不可覆盖
`-> number?`，虽然逻辑无害）。**保持严格，写进 charter §10**：一条规则、
零变异表；结果协变等真实需求出现再议（记录为可反证的排除，同 D43 第 68 条
的纪律）。纯文档，无实现动作。

## 第 77 条 —— 类家族的 match 必须可证穷尽（CLS-I3）

### 现状

枚举 match 漏分支报 VEL4015；类 match 漏分支**静默什么都不做**。

### 裁决：对齐枚举的严格度

- 主体静态类型是类（或类的联合）时，match 必须**可证穷尽**：
  以不可反驳 case 收尾（主体类型本身或其基类的 case、或 `case _:`），
  或联合的每个成员各有 case（`A | B` 由 `case A:` + `case B:` 覆盖 ——
  子类实例仍 `is A`，故成立）。
- 带守卫的 case 不计入穷尽（与枚举既有规则一致，审计已确认）。
- 诊断沿 VEL4015 的声音：「Match on Base 缺少兜底；类家族是开放的 ——
  以 `case Base:` 或 `case _:` 收尾」。
- 与 CLS-C3 呼应：不可反驳类模式**已经**参与非空返回分析，本条让穷尽性
  检查与返回分析口径一致。
- 回归：漏兜底被拒、基类收尾通过、`case _:` 收尾通过、联合全覆盖通过、
  守卫 case 不计入、枚举 match 不回归。

## 第 78 条 —— extern 类不可继承，列为有意缺席（CLS-I4）

现状被拒但消息误导（「Unknown base class」，像拼写错误）。真支持需跨桥
构造链，工程量大且边界多。

### 裁决

- **有意缺席**：charter §19 加条目，javascript-bridge.md 补一句。
- **定向诊断**：基类解析为 extern 类时报「extern 类不可继承；用组合包装
  实例，或把行为暴露为函数」—— 不再是「Unknown base class」。
- `extends Error` 不受影响（内建特例，既有）。
- 反证条件：出现无法用组合表达的真实站点再议。
- 回归：extern 基类定向拒绝、`extends Error` 不回归、消息断言。

## 第 79 条 —— setter 列为有意缺席 + 定向诊断（CLS-U1）

现状 `set x(v):` 得到三条级联通用错误，从不说「没有 setter」。

### 裁决

- charter §19 加条目：无 setter —— 赋值走字段或显式方法，getter 只读。
- 解析器识别类体位置的 `set name(` 形态，发**一条**定向诊断：
  「VelarScript 类没有 setter；写一个方法（`def setX(...)`）或直接赋值字段」
  （`get` 是软关键字有专门解析路径，`set` 获得同款识别但只用于教学拒绝）。
- 回归：定向消息单条不级联、名为 `set` 的普通方法/字段不受影响
  （`def set(...)` 合法）。
