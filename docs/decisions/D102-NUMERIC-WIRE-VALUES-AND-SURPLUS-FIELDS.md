# D102 — 枚举数值 wire 值与多余字段语义（用户裁决 2026-08-27）

两条裁决同场作出。证据来源：`@velarscript-labs/contract-codegen`（D101 L4）
对 `@velaros-ai/agent` 与 `@velaros-ai/kernel` 真实 wire 契约的生成报告。

## 裁决一：枚举成员 wire 值扩展到数值（采纳）

真实契约中 21 处 `z.literal(1)` / `z.literal(2)` 协议版本钉定（kernel 24 个
降级中占 15 个）在 Vel 侧只能降级 `unknown`，消费方失去协议版本校验——而
逐版本精确匹配正是这些 wire 协议的防漂移机制。

1. 枚举成员的 wire 值从「仅字符串」扩展为「字符串或安全整数」：

   ```velar
   enum KernelProtocol:
       v2 = 2
   ```

2. 这是**既有机制的完备化，不是新类型族**。charter「不添加结构化字面量
   类型」的守线原样保留；成员在类型位置、窄化、`match` 携带单例事实的
   行为不变；`Type.parse` 对数值 wire 值做严格相等校验（无强制转换，
   拒绝 `NaN`/`Infinity`/非安全整数字面量于声明处）。
3. 同一枚举内 wire 值按值身份跨字符串与数值统一查重；`values()`、
   格式化、LSP 呈现、文档同步。
4. `contract-codegen` 的 `z.literal(整数)` 映射随后跟进（labs 侧独立
   版本，另行提交）：单成员标签枚举或并入判别标签枚举。

## 裁决二：多余字段剥离为永久默认语义（维持现状）

zod `strictObject` 拒绝未声明字段；Vel 记录 `parse` 剥离之。真实契约
122 个 strict 对象翻译后全部放宽。所有者裁决维持剥离语义，原话：

> 「它没有说，那我当它不存在不是很合理吗，没必要报错。」

即：**类型即契约，契约外的数据对程序不存在。** 生成器把每处放宽计数
上报（`strict-unknown-keys` 类），跨进程 wire 的严格把关由声明该契约的
一侧（当前为 TypeScript/zod 侧）承担。

严格拒绝的 parse 变体**不进语言**。重开条件：出现第一个「必须由 Vel
自身拒绝多余键」的真实消费者场景。命名警示随案记录：该变体若重开，
不得命名为 `safeParse`——zod 生态中该词已固定为「不抛错、返回结果对象」
之意，同词异义违反正名原则（D28 的用语裁决同族）。

同场维持：可空单一规范形（`T?` 同时覆盖缺席与 null）不动，`null?` 不
可写维持 VEL2012；`.nullable()` 语义差（真实契约 66 处）作为已接受的
永久放宽由生成器计数上报。
