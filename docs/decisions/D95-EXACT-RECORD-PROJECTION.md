# D95：目标记录拥有精确投影（2026-08-24）

## 结论

具体记录类型新增编译器拥有的构造操作：

```velar
type TerrainSample:
    position: string

type GenerationSampleResponse extends TerrainSample:
    worldId: string

const sample: TerrainSample = {position: "0,0"}
const worldId = "world-1"
const response = GenerationSampleResponse.from(sample, {worldId})
```

目标类型是字段集合、类型、可选性与输出顺序的唯一权威。该操作解决的是“从
一个已经有静态记录类型的值构造另一个闭合记录”，不是给动态对象换一个类型
名字，也不是第二个运行时校验入口。

同时新增 advisory `A9`。当编译器能证明一个带目标类型的记录字面量只是从同一
来源逐个镜像同名字段，并加上少量无副作用覆盖字段时，提示上述规范形。

## 静态契约

`Target.from(source, overrides?)` 只对具体记录 Type 可用，包括已经具体化并命名
的泛型别名。原始泛型声明、基础类型别名、类、枚举以及一等 `Type<T>` 载体不
获得该成员。

1. `source` 必须是静态已知的记录形状；`unknown`/`any` 必须先经过
   `Type.parse`；
2. `overrides` 若存在，必须是一个不含 spread 的显式记录字面量；
3. 目标每个必填字段必须由来源中同名、可赋值的字段或覆盖项提供；
4. 目标可选字段在来源和覆盖项都缺失时省略；
5. 来源多余字段不会进入结果，也不会被检查；
6. readonly 来源的嵌套数据不得静默流入可写目标字段，除非显式覆盖。

投影是浅构造。它不复制嵌套记录或集合，不取消共享，也不解除 readonly
边界。`Type.parse` 仍负责不可信数据的有界验证与验证拷贝。

## 求值与运行时边界

位置参数和命名参数都按调用处书写顺序各求值一次，之后才开始选取字段。结果
按目标记录的继承字段、再到本地字段的声明顺序写入。

运行时只读取来源和覆盖记录的 own enumerable data descriptor。访问器、非可
枚举字段、缺失必填字段和非记录值全部失败关闭；来源的符号字段、原型字段和
额外字符串字段不会被投影。写入复用记录的数量上限、`__proto__` 防护、
`undefined` 归一化与响应式读取路径。

## A9 准入条件

以下条件必须同时成立：

1. 字面量位于一个具体目标记录的上下文中，并显式写出目标的全部字段；
2. 至少两个字段是 `field: source.field`，字段名相同、来源是同一个普通绑定；
3. 其余字段只使用标识符或字面量；
4. 来源有静态记录形状，且整个字面量没有类型诊断。

spread、调用、计算表达式、可选字段省略、混合来源、没有目标上下文或只镜像
一个字段时保持沉默。

Record 插入顺序可观察，所以 `.from` 会把不同书写顺序规范化成目标声明顺序。
报告必须明确说出这一点；若外部 wire 格式确实依赖原字面量顺序，作者在字面量
起始行写 `// velar-allow A9: <reason>` 保留它。该提示不带自动修复，避免删除
字段间注释。

## 覆盖

- 精确字段过滤、覆盖优先、继承与泛型别名、可选字段和目标顺序；
- 缺失、类型不兼容、`unknown`、动态覆盖、覆盖多余字段与 readonly 边界；
- 命名参数求值顺序、运行时独立输出和来源额外字段不泄漏；
- 跨模块字段表、格式化往返与仅具体记录拥有 `from`；
- A9 正例、无覆盖正例、所有静默边界及抑制三态。
