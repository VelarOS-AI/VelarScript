## 第 159 条 —— tarball 集合必须从 `packages/*` 派生

现状：**两份手抄清单**，权威是 `package.json` 的 `workspaces: ["packages/*"]`。

| 位置 | 形态 |
|---|---|
| `tests/package.acceptance.ts` | 八次字面 `pack("…")` |
| `scripts/release-toolchain.mjs:24` | 八元素字面数组 |

两份今天都对（`packages/` 恰好八个、全部 published），**但这是 D57 第 134 条那一族的第九例**。

**裁决：出一个命令，产出完整 tarball 集**，名单由 `packages/*` 派生
（按 `private !== true` 过滤），`package.acceptance.ts` 与 `release-toolchain.mjs`
**都改为调用它**。机制与波 N 刚建的 `scripts/velar-projects.mjs` 完全相同 ——
一个问题一个答案。

**收益不止防漂移**：报告说「最好由一个命令产出完整 tarball 集，不再让调用者
手抄依赖闭包」—— 那正是我犯错的地方。**清单存在，人就会抄错；命令存在，人就不用抄。**

## 第 160 条 —— 简报补三处（P1）

报告指名三处「简报缺，于是撞墙」，三处都属于**可发现性**而非语言缺陷：

1. **`--browser` 默认只跑 Chromium**，三引擎要 `--browser all`。
   `velar test --help` 里写了，**简报没写**，执行者是在阶段二允许读取的样例注释里
   偶然发现的。Tests 段补一句。
2. **函数型 component prop 的拼写**。执行者写
   `onAdd: (string, string) => Promise<null>`，得到 `VEL2001` 加**五条级联**，
   没有一条给出正确拼写；第二次猜才写对 `(title: string, author: string) -> Promise<null>`。
   **简报要把值级 `=>` 与类型级 `->` 并排展示** —— 报告明说「这里比 TypeScript 难用」，
   而难的原因是两种箭头没有一处并排出现过。
3. **`examples/tour/` 要在简报里可发现**。报告的量化结论：
   **若一开始知道 tour，阶段一那一轮返工会消失 —— tour 可消除本轮 2 次返工中的 1 次。**
   我们花了两波写它，而它「存在而不可发现，只能在任务书直接点名时产生价值」。
   简报末尾一句指路即可，不必展开。

## 第 161 条 —— 函数类型里误写 `=>` 收成一条教学诊断（P2）

现状是 `VEL2001 Expected ')' after grouped type` 加五条级联
（`Expected ':' before component body`、`Expected a newline…`、
`Expected an indented component body`、`Expected an expression`、`VEL2032`），
**没有任何一条说出 `->`**。

这违反语言的核心承诺（每个错误拼写得到一条命名唯一正确拼写的诊断）。
**裁决：在类型位置遇到 `=>` 时，给出一条直接教 `->` 的诊断，并抑制级联。**

判据同 D42 一路在拔的那类：**一堆级联错误里没有正确答案，等于没有诊断。**
