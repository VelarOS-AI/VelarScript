# D78 — 这门语言的定位（用户裁决 2026-08-16）

**推翻本场早些时候由我写下的定位。** 原文是
「一门由 AI 编写和维护、由人类阅读和拥有的语言」，
所有者读后的判断是：**「没有体现这门语言真正的意义」**。

---

## 第 195 条 —— 定位

> **面向 AI 时代的一门可扩展的编程语言，语言与框架一体化。**
>
> *An extensible programming language for the AI era, where the framework is
> the language.*

**这是所有者的原话，不是我拟的。** 他的说法是「我一直都是这个定位」——
也就是说这不是新决定，是**仓库一直在执行、而文案从来没说出来**的那一条。

### 为什么旧定位不对（记下来，免得将来又漂回去）

「AI 写、人读人拥有」回答的是**分工**——谁干什么。
定位要回答的是**这门语言本身是什么**。分工是真的，但它是下游：

```text
可扩展 + 语言框架一体化   ← 这门语言是什么
        ↓
一门语言覆盖结构/样式/状态/测试/服务端，编译器检查全部
        ↓
所以只留一种写法才有意义，所以敢不承诺兼容
        ↓
而这两件事付得起代价，是因为 AI 写、AI 改   ← 分工在这里
```

### 我在这条上犯的两个错，都记下来

1. **第一次纠偏时，我把所有者的「初衷」当成了定位**
   （「不希望用它的人有一天因为受不了 Vel 而重新设计一门语言」）。
   他的原话回复：**「这是我的初衷不是这门语言的定位」**。
   两者的区别是：初衷解释**它为什么会出现**，定位说明**它是什么**。
   两条都要有，但不能互相顶替 —— 见下面的文档结构。
2. **我拟的第一版英文写成 "language framework"**，
   所有者更正为**编程语言 + 语言与框架一体化**。
   差别不是措辞：「framework」会读成「语言之上还有一层」，
   而事实恰恰相反 —— `component`、`state`、`look` 是**关键字，不是导入**，
   框架**就是**语言。

## 第 196 条 —— 定位必须由「可扩展」和「一体化」两条一起成立

**这两条不是两个卖点，是同一件事的两面**，拆开任何一条都会塌：

| | 作用 | 拆掉会怎样 |
|---|---|---|
| **一体化** | 把需要验证的面收成一门语言 | 模型又要同时正确拼接六个生态，接缝回来了 |
| **可扩展** | 让上面那条不以 Core 变成垃圾堆为代价 | Core 认识 DOM、CSS、文件系统，攒成它当初要逃离的那一堆 |

**所以「Core 什么都不认识」是定位的一部分，不是内部纪律。**
本场我拦下的每一次边界违规（D53 的 `unsafe css` 归 web 而非 Core、
D62 的 Core 名册、`check-runtime-boundary` 的逐扩展审计）**都是在守这条定位**，
只是当时没人把它写成定位。

## 第 197 条 —— 定位文档的八问结构（所有者给的提纲）

所有者连续问出的八个问题，就是 `docs/why-velarscript.md` 的结构，
**按这个顺序**，不要合并、不要重排：

1. 它存在的意义是什么
2. 它能解决什么问题
3. 它为什么会出现
4. 它的设计宗旨是什么
5. 你为什么要选择它
6. 它的优点是什么
7. 它承诺什么
8. **不承诺什么**

### 三条内容硬约束

- **第 3 问是「初衷」的位置。** React 那一堆条框、Vue 的 template、
  「没有哪一条约束会逼人重写，是那一堆」——**全部放这里，不许上标题**。
  第 195 条已经裁定它不是定位。
- **第 3 问必须回答「为什么是现在」。** 删除一直在原理上可行、
  在实践上付不起（迁移是人力）。**变的是这一点**：作者是模型之后，
  破坏性改动的代价变成一次模型重写加一轮诊断。
  **Vel 在这一刻之前造不出来 —— 不是语法需要模型，是它的核心机制需要。**
- **第 8 问不许软化。** 永不承诺兼容、没有长周期稳定通道、
  生态广度要自己写边界、不换运行时、**迁移不免费**。
  一份只说承诺不说不承诺的定位文档是广告，不是定位。
