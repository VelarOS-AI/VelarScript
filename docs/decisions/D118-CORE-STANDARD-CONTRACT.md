# D118 — Core 标准承诺与边界裁决

2026-09-13，所有者要求先固定语言核心标准，再由模型完成实现与验收。
当前契约和实现账本见 [Core 标准](../core-standard.md)，详细语言规则见
[language-charter.md](../language-charter.md)。本文件记录裁决缘由。

OpenVoxel 暴露了逐字段 readonly、固定位置 List 返回值、有限状态匹配和能力发现
方面的实际问题。标准与实现交叉检查还发现整数/安全整数语义混用、结构验证路径
丢失、入口文档和语法名册过时，以及将永久命名空间笼统称为纯计算的错误分类。

据此确定：

- 按 D117 采用逐层只读；形状检查保留原有写入契约。
- 所有 match 统一要求完整覆盖，保留已有结构性覆盖证明。
- 业务多结果使用具名记录，通用两项配对使用 Pair，序列使用 List。
- 整数和安全整数分别拥有一致的成员谓词与语义验证规则。
- 结构验证与语义验证共享结构化路径，并明确诊断预算和不透明值边界。
- 可检查结构的字段与递归保证不因具名、匿名或跨模块传递而降低。
- 安装后的模型入口提供任务导向的能力地图和按需读取的版本匹配参考。
- Core 归属、永久名称和操作纯度分别判断。

每项设计都对应真实问题、公开承诺、边界和可执行验收；设计完成与实现通过分别
记账。工具链 0.34.0 在实现与完整验收完成后进入发布流程。
