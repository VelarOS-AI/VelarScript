# D81 — 规则的射程是「相对资产地址」，不是 `url()`（2026-08-16）

波 X2 把 CSS 资产扫描从正则换成 token 语法之后，**看清了一件原来看不见的事**：
同样会 404 的相对地址，还有两种写法，现行措辞一种都不拦。

---

## 第 202 条 —— VEL5037 覆盖相对资产地址的全部写法

### 现状

| 写法 | 现在 | 提取到 `assets/` 之后 |
|---|---|---|
| `url("./a.svg")` | **拦** | —— |
| `@font-face { src: url("./a.woff2") }` | **拦**（是 url token） | —— |
| `@font-face { src: src("./a.woff2") }` | **不拦** | **404** |
| `image-set("./a.png" 1x)` 的裸字符串 | **不拦** | **404** |
| `-webkit-image-set(...)` 同上 | **不拦** | **404** |

### 裁决：按理由划射程，不按函数名

**这条规则的理由写在它自己的诊断文案里** ——
「so extracted asset ownership stays explicit」。
资产归属这件事**分不出** `url()` 和 `src()`：两者提取之后都相对
`dist/assets/` 解析，都 404，都让归属变成隐式的。

**所以规则在论证上早就覆盖了它们，只是措辞停在了一个函数名上。**
这与 D50 第 92 条同源：**发布一条够不到某个位置的规则，
和发布一个够不到的名字，是同一种失败** —— 作者写下一个
真的会坏掉的东西，而工具说没事。

**措辞改述为「相对资产地址」**，实现覆盖 `url()`、`src()`、
`image-set()` / `-webkit-image-set()` 的裸字符串实参。

### 实施必须先验，不许照单全收

**上表是波 X2 token 化之后观察到的，我没有逐条复核浏览器行为。**
实施波要**先对每一种形态确认它是真实可写的 CSS**
（浏览器确实会据此发起请求），**再**把它纳入规则。

**一个都验不出来的形态不许加进去** —— 那会变成
「规则拦住了一个没人能写的写法」，正是 D50 第 92 条反对的另一面：
不可达的规则和不可达的名字一样没有价值。
**验不出来的，在报告里如实说，然后不加。**

### 不在射程内（写下来，免得将来重议）

- **`url()` 之外的相对路径本身**（例如 `@import "./theme.css"`）——
  已由 `containsCssImport()` 单独拦，不归本条。
- **报告全部还是只报第一条** —— 既有行为，本条不动它。
