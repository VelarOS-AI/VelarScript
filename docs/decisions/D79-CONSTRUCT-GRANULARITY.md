# D79 — 构造覆盖的粒度，与表达式侧的一个洞（波 U1 上报 2026-08-16）

D56 第 129 条建的 tour 覆盖门禁，**十八个类别全部是「名字」**。
波 U1 补上了第十九个类别 `statement-construct`（37 项，三张表派生），
并在补的过程中撞出两件它无权自己决定的事。

**两条都不阻塞发版**，都已经在门禁里以「洞」的形式**印出来**，
而不是被豁免表悄悄吞掉 —— 这是 D57 第 140 条那条纪律的直接应用。

---

## 第 198 条（待裁决）—— 共享一个 AST 节点种类的拼写，门禁要不要分得开

### 现状（实测，门禁每次运行都会打印）

| 一个节点种类 | 两种拼写 |
|---|---|
| `EmbeddedJavaScriptDeclaration` | `extern js(…)` / `unsafe js` |
| `VariableDeclaration` | `const` / `let` |
| `FunctionDeclaration` | `def` / `async def` |
| `ClassDeclaration` | `class` / `abstract class` |
| `ForStatement` | `for` / `async for` |

**没有任何编译器自有的表枚举这些分叉**，所以新类别只能要求到*种类*：
tour 两种内联块都写了，但**删掉其中一种不会让门禁变红**。

### 反例已经在树里，而且是它自己长出来的

Web 扩展的 `unsafe css` **是例外**：它的 `source` 是真正的标签联合
（`external` | `inline`），所以**两种拼写各自被单独要求** ——
波 U1 的第二次红色验证正是删掉内联块、**留着两行 `import css unsafe`**，
门禁照样红并点名。

**这说明代价已知且很小：一个联合。**

### 我的建议：做

`unsafe css` 已经把模式跑通了。**但这是 `packages/**` 里的 AST 形状改动，
不是门禁改动**，所以要你点头。

**代价我如实说，不止一个联合**：五个节点里有四个
（`const`/`let`、`def`/`async def`、`class`/`abstract class`、`for`/`async for`）
是**语言最核心的节点**，给它们加判别式会波及解析、类型、发射、格式化器
的大量 `switch`。`EmbeddedJavaScriptDeclaration` 是最便宜的一个，
且是本轮唯一有实证需求的一个。

**所以可以拆两步，第一步单独就值**：
1. **只给 `EmbeddedJavaScriptDeclaration` 加判别式** —— 一个联合，
   立刻让两种内联块各自被门禁要求。
2. 其余四对**另议**，它们的收益是纯粹的门禁粒度，代价是核心节点手术。

## 第 199 条（待裁决）—— `duration` 是个没有声明的节点，它挡住了表达式侧

### 实测

`packages/compiler/src/parser.ts:3486` 产出
`ExtensionExpression:core:duration`，写法是**一个没有接口、
不属于任何联合的裸 `as Expression` 强转**。

**后果**：一个照着 `CoreExpression` 映射出来的名册**会静默漏掉它** ——
也就是说，把 `statement-construct` 那套照搬到表达式侧，
**得到的会是一个假绿门禁**。这正是波 U1 把新类别**限定在语句**的原因，
而它把这个原因写进了报告而不是让它消失。

### 探针的负面结果，如实记（这是好消息）

除 `duration` 外，**表达式、模式、类型语法、类体的每一个种类，
tour 今天都已经覆盖**，唯一的例外是 `AssignmentExpression` ——
它是解析恢复节点（`ast.ts:800-805` 自己写着「它永远到不了代码生成」），
**按构造就是反向语料**，不该被要求。

### 我的建议：先给 `duration` 一个真正声明的节点，然后表达式侧才便宜

顺序是硬的，反过来做不成：**先有声明，才能派生名册**。
而一旦 `duration` 有了接口并进入 `CoreExpression`，
表达式类别就是把已经跑通的那套照搬一遍。

**注意这条本身就是一个缺陷，与门禁无关**：
一个 Core 自己的解析器产出的、却没有类型声明的节点，
是 D57 第 134 条那一族在 AST 上的形态 —— 权威表没有把它算进去。
**即使不做表达式覆盖，这个强转也该被消掉。**

## 排期

**两条都不阻塞 0.10.0。** 门禁已经如实打印它覆盖不到的地方，
所以不存在「以为覆盖了其实没有」的假绿 —— 那才是必须在发版前解决的东西。
