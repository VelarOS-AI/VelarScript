# D70 — 被冻结的响应式读取（用户上报 2026-08-16）

来源：官网的语言切换只切正文，侧栏与「本页内容」永远停在首次加载时的语言。
站点 bug 已由上报者修好；本文裁决成因。

---

## 第 179 条 —— 行为是对的，沉默才是缺陷（接受为缺陷）

### 事实链（我复验，编译干净）

```text
// locale.vel
export state siteLocale = "zh"
export def useLocale() -> Composer:
    return {text: (english, chinese) => siteLocale == "zh" ? chinese : english}

// 组件里
const locale = useLocale()
const frozen = locale.text("English", "中文")     ← 读取发生在 setup，冻结

return <div>
    <p data-frozen>{frozen}</p>                   ← 永不更新
    <p data-live>{locale.text("English", "中文")}</p>   ← 跟着切
</div>
```

**同一个函数、同一个组件、同一屏代码，一个冻结一个跟随。**
`velar check` → `Checked 2 modules`，零诊断。

### 上报者的判断我确认，并把它说得更硬

**`const x = <expr>` 冻结结果不是缺陷，是 `const` 的定义。**
D26 的属性级追踪追踪的是**读取发生的位置**，本行为与它一致；
而快照是合法需求（「记录用户打开页面时的语言」），
让 `const` 初始化自动变响应式会**删掉这个能力**。拼写也齐备：
要快照写 `const`，要重算写 `computed(() => …)`。**表达力上没有洞。**

**洞在于一个响应式读取被冻进了渲染输出，而编译器一声不吭。**

语言的自陈里写着「没有被静默丢弃的语句」，而且它执行得很严 ——
一个裸 `5` 是 VEL4030。**一个永不重算的界面标签，和 D69 那个永不触发的
`watch` body，是同一种静默丢弃的两个实例。两条都接受为缺陷。**

### 这一条比 D69 值钱，理由要记下来

- D69 的后果是「什么都没发生」，开发时容易察觉。
- **本条的后果是界面显示了错误的内容**，且只在特定交互路径上暴露。
- 它逃过了 `velar check`、55 个模块编译、294 个样本门禁、10 条浏览器测试，
  **以及所有人的眼睛**。
- 逃掉的原因最刁钻：**首次加载恰好是中文，所以中文用户永远看不出问题** ——
  写站点的人用中文测，永远测不出来。
- 它发生在 `docs-kit` 这种被反复审阅的共享组件里，不是角落。

## 第 180 条 —— 检测按运行时开发模式做，但**触发条件改成"发散"而不是"读取"**

### 三个方向的成本，我确认上报者的分档

我查过机器：`reactiveExports` 是 `Map<string, "state">` ——
它记的是**哪些导出是 state 绑定**，**不是**「调用这个函数会做响应式读取」。
所以「静态判定 `locale.text(...)` 会读 `siteLocale`」确实需要
**跨模块的过程间副作用分析**，与 D26 二期的逃逸分析同级。**分档正确。**

- 方向 2（语法近似）**排除** —— 上报者说误报会非常多，我同意，
  「setup 里的 const 初始化器调了某个结果进 JSX 的函数」几乎命中所有正常代码。
- 方向 3（完整摘要）**是真正的答案，与 D26 二期一起排期** ——
  **不是放弃**。写下这一句，是因为「加了个开发期警告」很容易让这件事永久结案。
- 方向 1（运行时开发模式）**先做**。

### 但我要改它的触发条件

上报者的方案是：**读取发生时**若无活动观察者且处在 setup 阶段，就记一笔。

**问题：它会对每一个合法快照都开火。** `const openedAt = siteLocale`
是正当的、有意的快照 —— **一条会对正确代码开火的警告，人们会学会忽略它**，
然后它就等于不存在。

**裁决：在"发散"时报，不在"读取"时报。**

- setup 阶段记下：哪些响应式来源在观察者之外被读了、读到的值、读取位置
- **当其中某个来源后来真的变了**，才报

为什么这个形态好得多：

1. **从不发散的快照从不报警** —— 而它既然从不发散，就没人可能被它伤到。
2. **真实案例照样被抓**：站点的语言切换正是「来源后来变了」。
3. **误报被压到只剩一类**：有意的快照 + 来源确实变了。那一类更少见，
   且消息可以点名它。

**这是「警告值得信」与「警告被关掉」的分界线。**

### 消息要说清三件事

冻结的是什么、在哪冻的（**要源映射回 `.vel` 行**）、
以及**如果本意是跟随，正确拼写是 `computed(() => …)`**。
不要写成一条泛泛的「可能有问题」。

## 第 181 条 —— 只在默认值上读过的响应式来源，等于没测

**这条是本次最可推广的收获，而它是一条测试纪律不是语言规则。**

上报者写道：既有浏览器测试只断言 `.primary-nav`，
**所以这个 bug 从头到尾都是绿的**；而首次加载恰好是中文，
中文用户与中文测试都看不出来。

一般化：**一个只在默认值上被读过的响应式来源，它的任何冻结读取都无法被检测。**
测试断言的是「默认值下界面对不对」，而冻结与跟随在默认值下**逐字相同**。

**裁决：这条写进最佳实践 —— 每个响应式来源，测试里至少要让它变一次。**

**并调查一条门禁的可行性**（不预判结论）：编译器知道每一个 `state` 绑定；
「本项目的每个 `state` 至少被某条测试改变过一次」是一个**可派生的覆盖问题**，
形状与 D56 第 129 条的展示覆盖率门禁同族。
**实施者调查后给结论与成本**，可行就建，不可行就说清为什么，写进最佳实践即可。
