## 第 118 条 —— `!` 不作为 `not` 的第二拼写

### 提议

用户 2026-08-15：「加一个写法 `!` 取反和 `not` 等价，写起来更方便，它和 `not`
应该有不同的用途。」

用户已注意到纯同义词的问题，因此要求两者**用途不同** —— 提议本身包含了对
规则 3 的自觉。听完下面的理由后，用户裁决**不改**。

### 裁决：不加。现状（VEL1005 教学诊断）保留不动

今天 `!ready` 的行为（`packages/compiler/src/lexer.ts:268`）：

```
VEL1005  Use 'not'; VelarScript uses readable logical operators
```

—— 带**机械修复**（`velar fix` 可改写）且**可恢复**（继续按 `not` 词法化，
文件其余部分照常分析，不产生级联错误）。这是本语言教学诊断的标准形态，
盲测两轮均实测「模型按 JS 习惯写 `!`，一轮被教会」。**它在正常工作**，
本条不动它。

### 理由

**一、这门语言的 117 条裁决里有一大族是在删双拼写。** 单引号（第 111 条）、
`removeLast`（D44）、`invert`、`deepEqual`、`import type`（第 100 条）、
裸副作用导入、JSX 的第三种定界符 —— 每一条的理由都是同一句话：
**一个概念一个拼写**。新增第二个取反，等于对着这一族说「刚才那些不算」。

**二、唯一能真正区分两者的机制，被本仓自己的证据证明「两头不讨好」。**
认真找过，候选只有**优先级**：`not` 松绑定（Python 侧，`not a == b` 读作
`not (a == b)`），`!` 紧绑定（JS 侧，读作 `(!a) == b`）。Ruby 正是这么做的，
而那是公认的疣。但本语言有更硬的证据 —— **D30 第 19 条已经证过这条路无效**：

> 对纯 bool 操作数，`(not a) == b ≡ not (a == b)`（两者都是 XOR），
> 其余情形被「操作数必须是 bool」拦住。

也就是说，在**人们最会伸手去用 `!` 的位置**（`!ready == expected` 这类布尔比较），
两种优先级**可证等价** —— 差异是零，"不同用途"是幻觉。而差异真实存在的地方，
恰恰是 `in` / `is` 这两个也落在比较层的运算符：`!a in list` 与 `not a in list`
会真的分叉。于是这条路的收支是：

- **常见位置：没有区别** —— 花一个新运算符买到零；
- **罕见位置：真分叉** —— 而且分叉方向要读者自己做案例分析才知道，
  同时 `not in` / `is not`（charter §549-550）本来就是这两处的正确拼写。

**在收益为零的地方付出复杂度，在有代价的地方制造陷阱** —— 两头不讨好。
另外语法审计（`COMPLETENESS-AUDITS.md`）本就把比较层撕裂双亲列为全语言
最高风险的一行；再放一个绑定强度不同的取反进去只会加重它。

按**位置**区分（例如只在 JSX 属性里允许 `!`）同样不行 —— 那是「同一表达式
换个位置改含义」，正是用户当初否决 `%` 标量徽章的那一类陷阱。

**三、最强的理由来自使命：读者可能不是程序员。** `not ready` 是一个英文词；
`!ready` 是一个先学过才认识的符号，且 `!` 在人眼里的第一直觉是「强调」而非
「否定」。Vel 的分工是 **AI 写、人读** —— 写的那一半不在乎多打三个字符，
读的那一半在乎。这条对齐 D49 的使命裁决。

### 顺带澄清：`not` 没有"啰嗦"问题需要补

排查过三个可能真实的痛点，都不是缺 `!`：

| 疑似痛点 | 实际归属 |
|---|---|
| `if not (user != null)` 读着别扭 | 缺的是**正向拼写**，不是缺 `!`；而正向拼写已经有了 —— `if user == null` |
| 否定成员测试 | 已有 `not in`（charter §549）作为直接反面 |
| 否定类型测试 | 已有 `is not`（charter §550）作为直接反面 |

即：**语言在每个否定高频位置都已经给了直接反面拼写**，`not` 只承担剩下的
纯布尔取反。这也是它不显得啰嗦的结构原因。

### 重开条件（证伪判据）

以下任一出现，本条重开：

1. 盲测中模型**被 VEL1005 教过之后仍反复写 `!`**（说明教学没生效，而不是拼写不够短）；
2. 出现**真实的**、`not` / `not in` / `is not` / 正向拼写四者都覆盖不到的否定位置；
3. 语言获得布尔以外的取反语义（例如位运算），届时 `!` 与 `not` 才真正**不同义** ——
   但那时该讨论的是那个新语义，不是 `!` 的便利性。

**不构成重开理由**：少打字符、与 JS 一致、"看起来更顺手"。前两条 D52 第 114 条
已立过同源纪律（「统一好看」不是理由），第三条是主观偏好 —— 主观偏好属于所有者，
所有者已经裁决了。
