# D53 — 内联外语源码块（用户裁决 2026-08-15）

用户提出：把原生 JS 写在反引号串里（JS 生态 `` html`…` ``/`` sql`…` `` 的成熟
做法），编辑器可据标记做语言注入；不支持插值但要有**注入通道**；允许**不写
声明、作者自负**。编排代理就 `ts`/`html`/`sql` 提出不同意见，用户**同意**该范围。

## 前提事实（实测，非推断）

- **内联 JS 今天已经能跑**，只是拼写惨不忍睹：
  `import js unsafe {hash} from "data:text/javascript,export function hash(t){…}"`
  —— 真实可执行（探针验证）。
- **而把同样的 JS 放进隔壁文件反而被拒**：`import js unsafe {x} from "./helper.js"`
  → `Relative JavaScript import target cannot be emitted; move it into a package`。
- 所以本条**不是新增能力，是给已有能力一个好拼写**，并顺带消灭上述不一致。

**为什么反引号串形态优于「Vel 文件内的 JS 语法块」**（编排代理原方案 B）：
JS 待在**字符串**里 —— Vel 的解析器根本不需要认识 JS 文法，格式化器不必处理
外来语法，诊断不必跨语言。编辑器侧靠标记做注入，是 JS 生态已验证的路子。
反引号是 D46 刚落地的载体，现成。

## 第 117 条 —— `extern js` / `unsafe js` 内联源码块

### 形态一：带契约（受检，推荐）

```
extern js(factor: number, prefix: string)`
    export function scale(n) { return n * factor }
    export function label(n) { return prefix + n }
`:
    export def scale(n: number) -> number
    export def label(n: number) -> string

print(scale(21))
```

- `extern js` + 反引号串 = **模块源码**；`:` 后缩进块 = **契约**，与既有
  `extern module "pkg":` 的形状**完全一致**（零新概念）。
- 名字**直接进作用域** —— 没有外部模块可指名，故不需要 `import`。
- **副作用值得记**：内联块比 `import js unsafe` **更受检** —— 契约就在下面三行，
  不存在「整个模块变 any」。

### 形态二：无契约（作者自负）

```
unsafe js`
    export function whatever() { return globalThis.someLegacyThing }
`
```

- 导出的一切是 `any`；**必须写 `unsafe`** —— 该词在本语言里已经是「我自己负责」
  的唯一说法（`import js unsafe`、`import css unsafe`、`unsafe:html`），
  **复用而不发明第二个**。
- 这比现状**更诚实**：`import js unsafe` 是整个模块隐式变 any；显式块一眼可见。

### 注入通道：参数绑定，不是文本替换

**不支持插值**（串按 raw 语义：`\n` 是两个字符，`${}` 与 `{}` 都是字面文本）。
值经**捕获参数表**跨界：括号内声明的名字在 JS 模块作用域里是**真正的绑定**
（发射为模块参数），不是拼进源码的文本。

理由：文本插值等于**用字符串拼接生成代码** —— 注入风险，且读者要在脑内跑一遍
拼接才知道最终代码长什么样。**值走契约，不走文本**，这正是契约存在的意义。

### `css` 同规则 —— **但归 web 扩展所有，不进 Core**（用户 2026-08-15 更正）

```
unsafe css`
    @keyframes shimmer { from { opacity: 0.4 } to { opacity: 1 } }
`
```

内联 CSS 与外部 `import css unsafe "./x.css"` 同语义（`before`/`after look`
的定位规则一并适用）。**它是真需求**：审计确认 keyframes 之外的动画今天只能靠
原生 CSS，而唯一的路是引外部文件。CSS 无「契约」概念，故只有 `unsafe` 形态。

**所有权边界（用户明确更正，最高约束）**：

| 块 | 归属 | 理由 |
|---|---|---|
| `extern js` / `unsafe js` | **Core** | JavaScript 是母体运行时，Core 本来就发射并对接 JS —— `extern module` / `import js` 一直是 Core 的能力 |
| `unsafe css` | **web 扩展** | **CSS 是 web 的概念，Core 不该认识它**。`import css unsafe` 今天就由 web 扩展拥有，内联形态必须落在同一处 |

**通则（本条据此重申）**：**哪个模块该支持哪些东西的边界不能破坏。**
Core 不认识 CSS、不认识 DOM、不认识能力模块 —— 这与 charter 规则 5 同源，
也与 D51 第 96.2 条（能力可释放性用结构判定而非把 `FileWatcher`/`Server`
写进 Core）是同一条纪律的两次应用。**在 Core 里放一个 `css` 关键字，等于为了
少写一行扩展注册而破坏分层** —— 不接受。

实施要求：`css` 块的词法/解析/发射全部由 `@velarscript/web` 注册（走既有的
扩展协议，与 `import css unsafe`、`look:`、`keyframes:` 同一套）；Core 项目里
写 `unsafe css` 得到 D37-45 那族的 web 扩展指引，而不是「未知关键字」。

### 明确不做（连同理由，供将来复核）

| 候选 | 不做的理由 |
|---|---|
| **`ts`** | ① 要背一个 TS 编译器进工具链（版本/tsconfig/装饰器/路径映射，长期流血的依赖）；② **收益很窄** —— TS 类型**不跨进 Vel**，契约照样要在 Vel 侧声明，所以只买到「块内部有类型检查」，而块内部按定义是几行逃生代码；③ **两套类型系统同处一文件且互不认识**，对「人来读」是最坏形态；④ 真要写 TS 说明规模已够大 —— 那该是独立的包（现成的路） |
| **`html`** | Vel 已有 JSX 与 `unsafe:html`，再加一个是第三种拼写 |
| **`sql`/`graphql` 等纯标记** | 它们**不执行**，标记纯给编辑器看 —— 于是制造了同一字符串值的第二种拼写（`` sql`SELECT 1` `` 与 `"SELECT 1"` 值相同），收益只有高亮；且词汇表开放则打错字静默失效、封闭则要维护「祝福哪些语言」的表。**更好的办法**：Vel 自有 LSP 按**参数类型**注入 —— 库把参数声明成 SQL，编辑器自动按 SQL 高亮，**零新语法、对任何库自动生效**、AI 不必记住合法标记 |

### 角落已裁决（2026-08-15，实测证据见下节）

下面六条原本挂给实施者，现由编排代理**以实测证据**定案。实施者按此执行，
不再自行取舍；若实测与此处结论冲突，停下上报，不要静默改设计。

| # | 角落 | 裁决 |
|---|---|---|
| 1 | 位置 | **仅模块顶层**（与 `extern module` 一致）。函数体内的块会让「这段 JS 何时求值」不可见，且与形态 3 的独立文件发射天然冲突 |
| 2 | 多块互引 | **各自独立模块、互不可见**。要共享就合成一个块。形态 3 定案后这条是自动结论：一块一文件 |
| 3 | 发射形态 | **每块发射为一个兄弟 `.js` 文件**，并携带指回 `.vel` 的 source map。**不用 `data:`，不用运行期求值** —— 理由见下 |
| 4 | CSP | **不构成阻碍**，但**约束了形态**：见下 |
| 5 | `velar fix` | **入家族**。`data:text/javascript,` 旧形态 → 块形态是可证等价的机械改写，且**严格改善可调试性**（旧形态的 source map 不可用，见下）。按第 95 条判据成立 |
| 6 | 相对 `.js` | **仍不做**（维持 D53 原判），但记下新证据供将来复核：见下 |

#### 第 7 条角落（2026-08-21 补裁）：内容行恰好只有一个反引号

上面六条没有覆盖终止符自己的那个角落，实施中撞上，在此定案。

**裁决：无逃逸，维持结构化终止符。** 位于声明缩进、整行只有一个反引号的行
就是本块的终止符（受检形态是反引号加 `:`），无论它上面的 JavaScript 作何解释。
模板字面量或块注释的反引号若落在这样一行上，块在此提前结束，其后的内容不再属于
这个块。

取无逃逸而不是发明一个逃逸字符，理由与形态一致：终止符是**结构**规则，它按
定义不读 JavaScript；一旦为它开一个逃逸，块的边界就要靠解析块内语言才能确定，
而这正是「不用 `eval`、构建期可解析」那条下界要避开的东西。改写的成本也接近零
—— 把那个反引号缩进一格，或写在上一行内容的末尾，两种写法实测都照常编译。

**编译器点名这条规则，但只以条件句点名。** 载荷被截断后解析失败时，`VEL2037`
的 JavaScript 语法错误后面追加一句提示（`structuralTerminatorHint`），三种触发
实测如下：

| 截断处 | Acorn 消息 | 提示 |
|---|---|---|
| 模板字面量的收尾反引号独占一行 | `Unterminated template` | 「若这个字面量本想越过这样一行，块已在那里结束 —— 缩进那个反引号，或把它写在内容行末尾」 |
| 块注释里的反引号独占一行 | `Unterminated comment` | 同一条规则，改说注释 |
| **开启**的反引号独占一行 | `Unexpected token`（什么也没点名） | 由结构判定：在截断处补一个空模板字面量重解析，能解析通过才给提示 |

提示以条件句陈述规则，而不是断言本块就是这样结束的 —— 载荷抵达诊断时已经无法
区分「被终止符截断」「作者本就没有收尾」「块根本没有闭合」三种成因。

**一个形状点名不了**：截断后的残余**本身就是一个合法模块**时（`export const t =
String.raw` 在它的标签模板之前被切断），块内不产生任何 JavaScript 诊断，切下来的
后半段变成 Vel 源码并报出与本规则无关的错误。要分辨这一种，需要看块后面那一行，
而那只有词法器看得见。本条不为它另加机制：那是「同一个想法的第二种拼写」。

规范一侧归 charter 的 Inline foreign source 一节；本条只记裁决与实测证据。

#### 证据一：CSP 不是阻碍，因为 bundler 先一步吃掉了它

生产 web 构建是 `esbuild` + `bundle: true`（`packages/cli/src/production-build.ts:78-98`），
而 **esbuild 在构建期就把 `data:text/javascript,` 导入内联掉**（实测：产物里直接是函数体，
没有任何 `data:` 残留）。CSP（`packages/web/src/host.ts:154`）是 `script-src 'self'`，
浏览器**根本看不到** `data:` 源。开发态另有豁免：CSP 只在非 development 注入
（`host.ts:81`）。Node/CLI 侧无 CSP。

**但 CSP 钉死了形态的下界**：`script-src 'self'` 不含 `'unsafe-eval'` 也不含
`'unsafe-inline'`，因此发射**只能是静态导入形状、构建期可解析**——
**运行期 `eval` / `new Function` / 注入 `<script>` 一律出局**。这条要写进实施要求，
它是本特性唯一真正的硬约束。

#### 证据二：形态由 source map 决定，而不是由偏好决定

两种候选实测对比（`--sourcemap` 后读产物 map 的 `sources`）：

| 发射形态 | 最终 map 的 `sources` | 可调试性 |
|---|---|---|
| `data:text/javascript,…` | `["dataurl:data:text/javascript,export function hash…"]` | **不可用** —— 合成名字，编辑器与 devtools 都打不开 |
| **兄弟 `.js` + 指回 `.vel` 的 map** | `["app.vel", …]`，且 `sourcesContent` 带着 `.vel` 原文 | **可用** —— esbuild 会**链式合并**上游 map，作者在 devtools 里步进到的是自己的 `.vel` 行 |

D53 原文要求「无论哪种形态，必须 source-map 回 `.vel` 行号，否则逃生通道自己
变成不可调试的黑箱」——**实测表明只有兄弟文件形态能满足它**。形态由此定案，
不是取舍。

#### 证据三：为什么第 6 条（作者手写相对 `.js`）仍然不做

新事实：兄弟文件形态证明了**编译器发射相对 JS 是安全的**（esbuild 会解析并内联）。
这似乎松动了现有的 `Relative JavaScript import target cannot be emitted` 拒绝。

**但两者不同**，且差别正是拒绝的理由：编译器发射的兄弟文件**由编译器负责搬运**；
作者手写的 `./helper.js` 则要求编译器保证一个它不拥有的文件出现在产物里 ——
在 `bundle: true` 的生产路径上能成，在**不打包的路径**（`velar run`、库构建）上
不成。**该拒绝针对的是这个不对称，不是相对路径本身。**

维持 D53 原判（本波不做，先给一条好拼写），理由不变：盲测与裁判迁移**一次都没
撞上「我需要写原生 JS」**。将来若真实频率上来，重开时的正确问法是
「**不打包路径怎么搬运**」，而不是「相对导入能不能解析」。

### 原始的待定角落（已由上节全部裁决，保留供对照）

1. **位置**：编排代理倾向**仅模块顶层**（与 `extern module` 一致）；函数体内的
   块会让「这段 JS 什么时候求值」变得不明显。
2. **多块互引**：倾向各自独立模块、互不可见（要共享就合成一个块）。
3. **发射形态**：独立模块文件 vs 内联；无论哪种，**必须 source-map 回 `.vel`
   的行号**（否则逃生通道自己变成不可调试的黑箱）。
4. **CSP**：生产构建的 CSP 是钉死的（有验收门禁）。内联 JS 必须以**不违反 CSP**
   的形态落地（大概率是发射成独立文件而非 inline script）—— **这条必须先想清楚
   再动手**，它决定形态 3。
5. **`velar fix`**：`data:text/javascript,` 旧形态可机械改写为新形态吗？若可证
   等价则入家族（D50 第 95 条判据）。
6. 相对 `.js` 文件是否随之放开 —— **本波不做**：先给一条好拼写，别一次给两条；
   盲测与裁判迁移**一次都没撞上「我需要写原生 JS」**，真实频率待观察。

### 回归

带契约块的受检调用（执行级）、捕获参数真的跨界且类型受检、`unsafe` 块的 any
传播、插值不发生（`${}`/`{}` 是字面文本）、CSS 块与外部 import 同语义、
source-map 落在 `.vel` 行、CSP 生产构建通过、块内语法错误的诊断落点。

角落裁决带来的三条**额外**回归（缺一不可）：

1. **产物里不得出现 `eval` / `new Function` / 注入 `<script>`** —— 钉死形态下界的
   那条 CSP 约束，用产物扫描断言，不靠代码审查。
2. **source map 链式合并成立** —— 生产构建后读最终 `.js.map`，断言 `sources`
   含 `.vel` 路径且**不含** `dataurl:` 前缀的合成名。这条直接钉住形态三的实测结论，
   将来谁改回 `data:` 都会当场变红。
3. **`velar fix` 的 `data:` → 块改写双向幂等**，并附一条**执行级**等价证明
   （改写前后跑同一断言），因为第 95 条判据要的是可证等价，不是形状相似。
