用户于 2026-08-12 口述语言定位并要求传递给未来使用者（原话要点：解决 AI 时代
模型写代码不可维护的问题；面向没有太多编程水平的产品人等非程序员；建立在 JS
之上因 JS 难学坑多、写出来的代码千奇百怪普通人无法维护；希望成为人和 AI 共同

周期产品，长生命周期等未来稳定版）。

定位一句话：**Vel 是「AI 写、人拥有」的语言 —— 人给意图，AI 写码，编译器守门。**

非程序员不必调试他看不见的 bug 类别；正常语言用法 = AI 零样本可写；可读 JS
产物 = 永远有退路。盲测是核心 KPI 而非营销数字。

## 第 32 条 —— AI Skill 内置分发

### 目标

任何 AI 代理在 Vel 项目里工作时，无需外部文档即可加载一份语言速成简报；
简报随安装包分发，源与副本永不漂移。

### 交付物

**正典源已落地**：`docs/best-practices.md`（最佳实践典章，核心宗旨「AI 写和改，
人来读」成文其中；全部代码围栏过 check:docs，教错拼写=门禁红 —— 落地当天即
抓获两处笔者自己写的不存在拼写：匿名结构类型 `-> {a: number}` 与
`List<{...}>`，防漂移设计首战生效）。简报的惯用法部分从典章蒸馏，不另立正典。

1. **一份代理无关的 markdown 简报**，真源放 `docs/ai-skill.md`：
   - 身份段：Vel 是什么、双亲是 JS/Python、「按你已会的写，编译器会教你剩下的」。
   - **零样本易错表**（内容直接取材四期盲测 D 项与本次评审的双亲陷阱探针）：
     `f"{x}"` 而非 `${}`；`//` 而非 `#`；`def` 而非 `fn`/`function`；`type` 而非
     `record`/`interface`；`.size` 而非 `.length`；`.append` 而非 `.push`；条件只判
     bool、判空写 `!= null`；`case _:` 兜底；语句一行一条；无 `++`；`x = not x`；
     `range` 需导入；布局字符串开闭规则；children 是 `children: WebNode` prop；
     具名实参用 `=`；`match` 分发惯用法；`str()`/f-string 只收文本白名单等。
   - 核心声明速查表（def/type/enum/class/component/state/action/look 各一例）。
   - 惯用法食谱（资源读取 `value != null`、枚举分发、错误处理、JSX 条件渲染）。
   - **逃生通道指引**（指向第 33 条 playbook）+「相信诊断：它会点名唯一拼写」。
   - **体积预算 ≤ 600 行**，面向上下文窗口设计；宁缺勿滥，长尾交给诊断。
2. **三条分发路径**：
   - `@velarscript/cli` 包内打包该文件；新增 **`velar skill`** 命令原样打印到
     stdout（任何代理/工具一条命令拉取）。
   - **create-velar 脚手架生成项目根 `AGENTS.md`**（主流编码代理自动读取的
     约定文件），内容 = 简报正文 + 本项目门禁命令（`velar check` / `velar test`）
     + 逃生通道指针。
   - 官网一页（发布阶段并入官网任务）。
3. **防漂移门禁**：
   - 简报中全部 velar 围栏经 `check:docs` 编译（教错拼写 = 门禁红）。
   - 永久测试断言打包副本与 `docs/ai-skill.md` 逐字节一致（沿用 API 清单纪律）。
   - 体积上限断言。
4. **维护规则（写进批次纪律）**：此后每个 clean-break 批次必须在同一提交内更新
   简报对应条目 —— 简报即语言的镜子，镜子不更新门禁不绿。

### 排期

**批次 J**：H 落地后立即执行（简报 v1 反映当时语言现状；后续批次按维护规则
逐批更新 —— 规则从第一天就生效，A 批撤 `invert` 时简报同步改）。

## 第 33 条 —— JS 逃生通道建设（「防止项目开发到一半崩溃”）

### 目标

任何「Vel 缺了什么 / Vel 坏了什么」的时刻，开发者（或 AI）在五分钟内找到
不弃坑的出路。逃生通道是产品承诺，不是民间传说。

### 交付物

1. **`docs/escape-hatches.md` 决策树指南**（同时并入 AI 简报摘要版）：
   - 缺标准库能力 / 要用 npm 第三方包 → `extern module`（受检 ABI，首选）；
     形态无法声明（重载、按事件变签名 —— W-23/W-25 已知债）→ 当前诚实解法：
     `(payload: unknown) -> null` + 运行时收窄，或固定 adapter facade。
   - 快速粗接 → `import js unsafe`（进来即 `any`，边界处用 `Type.parse` 验证）。
   - Look 覆盖不了的样式 → `import css unsafe "./x.css" before|after look`；
     受信 HTML → `unsafe:html`（字符串边界，样式同样走 unsafe css）。
   - **疑似编译器缺陷挡路** → 最小复现 + issue 模板（沿用盲测账本三段结构：
     想写什么 / 编译器说了什么 / 怎么解决的）+ 临时绕行谱系（改写拼写 →
     extern 包裹 → 最终出口）。
   - **最终出口：可读 JS 弹射**。`velar build --mode readable` 产物是可读 JS，
     需要映射时再独立加 `--source-maps` —— 拿走产物继续开发，不回 Vel。
     反锁定是承诺的核心。
2. **弹射路径门禁化**：永久验收 —— 构建产物在**无 Vel 工具链**的空目录中独立
   运行（package acceptance 已有近似形态，把「反锁定」二字变成被测契约）。
3. **W-23/W-25 挂账**：extern 重载/按事件签名是逃生通道的已知窄口，在
   escape-hatches.md 里如实标注「当前解法 + backlog 链接」；不在本批实施。

### 排期

批次 J（与第 32 条同批：简报引用 playbook，必须同批成文）。
