# D62 — Core 缺两份可枚举名册（2026-08-16）

来源：覆盖率门禁（D56 第 129 条）建成后，实施波报告了两张**它想反查却读不到的表**。
读不到本身就是发现。

---

## 第 157 条 —— Core 的上下文关键字必须有一份可枚举名册

### 现状：没有原件，只有四份互不相同的抄本

| 位置 | 它知道的 |
|---|---|
| `parser.ts:65` `statementStarterWords` | `{"match"}` —— **一个词，且模块私有** |
| `parser.ts` 内联 `checkWord("…")` ×8 | `type` / `case` / `as` / `from` |
| `parser.ts` 内联 `this.current().value === "…"` | `test` / `using` / `init` / `dispose` / `constructor` |
| `formatter.ts` `statementHeadKeywordWords` | `{match, case}` —— 私有 |
| `language-server.ts` `coreCompletionItems` | 又一份关键字标签清单 |

**这是 D57 第 134 条那一族最纯粹的形态**：前面七例都是「有权威来源，却另抄了一份」；
**这一例连原件都不存在** —— 每个消费者各自发明了一份部分抄本，
而它们没有一份是完整的。

### 后果已经可见

1. **覆盖率门禁查不到这一族。** 扩展的 10 个上下文关键字被查了（web 扩展提供
   `lexical.contextualKeywords`），Core 的这一族查不到 —— 门禁只能把这个洞打印出来。
2. **charter §3 就这一族作了一条横切断言**（每个词在绑定、参数、循环绑定、
   具名实参、记录字段、成员名、记录简写七个位置都可作普通名字）。
   **那条断言所指的集合，今天没有任何东西能列举。** 展示的第 16 章是手写覆盖它的，
   而手写覆盖无法证明完整。

### 裁决

**从编译器导出一份 `CORE_CONTEXTUAL_KEYWORDS`，并让 parser 反过来读它。**
机制与 D57 第 135 条给常驻/前奏名册的做法完全相同（`core-vocabulary.ts` 是现成的家）。

实施要求：

- parser 的内联字面量**全部改为读名册** —— 只删抄本不建原件等于换个地方再抄一遍。
- `formatter.ts` 与 `language-server.ts` 的两份抄本同样改为派生。
- 名册落地后，**覆盖率门禁把这一族加进必需集**（它今天打印的那个洞随之关闭）。
- **不许用正则爬 parser 源码来凑名册** —— 实施波正确地拒绝了这条捷径：
  那会把 `invert` 这类**已删除**的语句一起要求回来。

## 第 158 条 —— Core 的数字后缀同样要可枚举

`Lexer.numericSuffixes` 是私有字段，所以 Core 自有的 `ms` / `s` 读不到。

**它们今天之所以还能被门禁要求，纯属侥幸**：web 扩展经 `LOOK_UNIT_TYPES` 又发布了
这两个后缀。**一个纯 Core 的检出会两个都不检查。**

**裁决：一并导出。** 判据与第 157 条同 —— 覆盖率门禁的价值取决于它反查的表
是否等于语言的真实表面；一张读不到的表，等于那部分表面没有门禁。

## 覆盖率门禁自己的两处记录（不是缺陷，是结论）

### 豁免表在当前形态下是「声明」而非「减法」

八条豁免全部登记并逐次打印，**运行时没有任何一条实际扣掉必需名**。
原因是门禁反查的是**正向词汇表**，而反向语料（`var`、`switch`、被排除属性…）
**按定义不在正向表里**。

这是个好结果，也值得写下来：**D56 第 133 条那张豁免表的真实作用是记录判断，
不是缩小检查范围。** 将来若有人往里加一条真能扣掉名字的豁免，
那才是需要重新审视的时刻。

### 它在自己身上抓到了「覆盖面低于自称」

第一版让豁免**跨类别泄漏**：`is`/`pass`（既是枚举保留成员名、又是硬关键字）
与 `display`（既是 Look 属性、又是被排除的媒体主语）被静默扣掉。
**门禁会说自己查完了，而它少查了三个名字。**

这正是本仓这两天反复撞到的那一类（合并三个扩展让后来者覆盖先前者、
子串断言假装在验证链接、`check:format` 因语料缺失而绿）。
**记在这里是因为它是第一例被作者在交付前自己抓到的** ——
豁免的作用域改成「只在声明它的类别内生效」，并在脚本里写明了原因。
