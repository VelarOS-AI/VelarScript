# VelarScript 0.3 Acceptance Matrix

Status: stable Web API and application-scale milestone complete

## Stable Web platform

| Contract | Evidence |
| --- | --- |
| Official Web API has one compiler/runtime authority and reports API version 0.3 | `0.3 standard Web APIs have one versioned compiler/runtime contract` |
| `web.base` applies equally to assets, `Router`, `Link`, and `navigate` | Standard-runtime source assertion and real Chrome `/app/` navigation |
| HTTP exposes lazy generic requests plus response/json/text/blob/type parsing | Standard-module interface/runtime contract test |
| Storage exposes explicit validated reads plus set/has/keys/remove/clear | Standard-module interface/runtime contract test |

## Application scale and HMR

| Contract | Evidence |
| --- | --- |
| Project results report total, compiled, reused, affected modules and duration | Compiler project statistics and `/__velar/status` |
| A 121-module project recompiles only its 41-module reverse dependency closure and reuses 80 modules | Application-scale incremental budget test |
| Dev rebuilds use the incremental compiler rather than recompiling the full graph | Three-module dev-server status integration test |
| Installed/workspace npm Velar source roots are watched outside the application root | External symlinked package HMR integration test |
| Changes arriving during a compile schedule a following rebuild rather than being dropped | Dirty-revision serialization in the dev-server coordinator |

## Browser and production observability

| Contract | Evidence |
| --- | --- |
| Real Chrome automatically checks initial render, reactive child props, class updates, base-aware navigation, deep-route refresh, and error-free logs | `npm run test:browser` using the browser DevTools protocol without a simulated DOM |
| Dev status is machine-readable | `/__velar/status`: API version, readiness, diagnostics, compilation statistics, package names |
| Production builds have deterministic identity and module/package composition | `velar-build.json`: build ID, compiler/API versions, module summary, asset roles, sizes and SHA-256 |
| Reusable npm library validates exported type, function, nested components, children, scoped CSS, and internal relative modules | `@velarscript/demo-web-kit` and the production Web example |

## Acceptance commands

```text
VelarScript: npm run check && npm test
Browser:     npm run test:browser
Example:     velar check/test/build examples/production-web
Workbench:   bun run check
Packaging:   bun run package:app:dir && bun run verify:app:dir
```

## Next big stage

Velar 0.4 is the distribution and broader Web-application stage: publishable
toolchain packages, project creation and version policy, a deliberately
limited TypeScript declaration bridge for real npm libraries, broader browser
coverage, and deeper routing/forms/head/accessibility APIs. SSR/server,
`velar/game`, a custom package registry, a custom debug protocol, and complex
type-level programming remain deferred.
