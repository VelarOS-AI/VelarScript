# VelarScript 0.5 Acceptance Matrix

Status: pre-release productization milestone complete

## Release integrity

| Contract | Evidence |
| --- | --- |
| Compiler, Web, creator, and CLI tarballs have one exact version and dependency identity | Release rehearsal manifest and package consumer test |
| Unchanged sources create identical package SHA-256 identities | Repeated rehearsal assertion |
| Rehearsal records source/tree/package identity and never publishes | `velar-toolchain-release.json`, workflow/source assertions |
| Strict candidates require stable version, clean tagged commit, matching remote, and license | Candidate refusal test |
| CI provenance uses OIDC artifact attestation without registry credentials | Release workflow contract test |

## Static Web production

| Contract | Evidence |
| --- | --- |
| Builds use isolated staging and remove stale output | Project build integration test |
| Generated HTML, fallback, and manifests cannot be overridden by public assets | Reserved-file refusal plus last-good-output assertion |
| Default production CSP blocks inline scripts and constrains resources | HTML/header assertions and production browser matrix |
| Additional network/image sources accept only secure origins | Configuration validation test |
| Static deployment manifest defines base, SPA fallback, headers, and caching | `velar-deploy.json` assertions |
| Build manifest format 2 hashes deployment files and records their roles | Production manifest test |

## Real Web application

| Contract | Evidence |
| --- | --- |
| Release Studio compiles 13 modules across pages, components, app modules, and a Velar package | CLI check and development status |
| Application exercises typed data, keyed lists, async HTTP, forms, Head, routing, state, storage, scoped CSS, and safe JS packages | Source application and browser flow |
| Chromium, Firefox, and WebKit pass both development and CSP production flows | Six-engine-mode Playwright matrix |
| Deep routes reload through the static SPA fallback | Production browser reload assertion |

## Compiler/editor independence

| Contract | Evidence |
| --- | --- |
| Workbench installs the packed compiler/Web/creator/CLI release set into a temporary project | `test:velar:installed` |
| Generic Workbench resolves project-local `node_modules/.bin/velar` | Installed-toolchain LSP acceptance |
| Diagnostics and completion come from the installed LSP with protocol v1 | Cross-repository acceptance result |
| Workbench contains no compiler dependency or duplicated Velar semantics | Existing product-boundary tests |

## Acceptance commands

```text
Velar:       npm run check && npm test
Packages:    npm run test:packages
Release:     npm run release:rehearse && npm run release:verify -- release/rehearsal
Browsers:    npm run test:browser
Example:     velar check/test/build examples/production-web
Workbench:   bun run check
Cross-repo:  bun run test:velar:installed -- /absolute/path/to/release/rehearsal
Packaging:   bun run package:app:dir && bun run verify:app:dir
```

## Next big stage

The former external-preview plan has been superseded. Velar 0.6 first matures
the object model, Core standard library, and Web APIs. External release work is
deferred until that language milestone is complete and separately authorized.

SSR/server execution, a custom registry, a custom debug protocol, complex
type-level programming, and `velar/game` remain deferred.
