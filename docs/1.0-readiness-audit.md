# VelarScript 1.0 Readiness Audit

Status: internal audit and public source identity complete; hosted preview and release not authorized; no production-ready claim

This audit starts from the completed 0.9Z engineering sequence and checks the
product from an ordinary application team's point of view. It does not treat a
large compiler suite as sufficient evidence and it does not itself authorize a
tag, npm publication, or hosted deployment. Public source publication was
authorized separately: the compiler/framework work is retained in draft PR #1,
and the official Website is its own public Apache-2.0 repository.

## Audit areas

| Area | State | Current evidence or required work |
| --- | --- | --- |
| New-project workflow | Passing internally | Packed compiler/Web/creator/CLI tarballs create default Web, routed docs, and reusable Web component projects, install into those projects, and run their own format check, semantic check, Core test, production build, artifact verification, and Chromium browser test scripts. The component package publishes its checked `velar.entry` plus README and keeps its preview separate. The same creator also checks and tests a framework-free Core source-library template. |
| Source maintenance | Passing internally | `velar format [file or project] [--check]` recursively owns manifest source and excludes `.git`, dependencies, public assets, and build output. |
| Data integrity | Passing internally | Official JSON, local/session storage, IndexedDB, HTTP JSON bodies, and WebSocket `sendJson` share strict finite primitive/record/dense-List validation. Known Map/Set/class/function values fail checking; dynamic lossy/cyclic values fail before storage, fetch, or socket side effects. |
| Standard/Web API parity | Passing internally | Every compiler-declared official module export is imported from its shipped runtime and compared exactly. Full behavioral and browser matrices remain required separately. |
| Language surface | Passing internally | Core boundaries are unified. Runtime Type arguments fail early, async/time inputs are strict, and test matchers are subject-typed. Class constructors contain only caller inputs while typed instance/static fields own internal state; one synchronous `init:` block enforces post-field invariants, typed read-only `get` properties cover derived data without setters, and one native-backed `private` modifier covers constructor/body fields, getters, and concrete sync/async methods without a `public`/`protected` hierarchy. Getter abstract/override contracts, `super.name`, module identity, and property-shaped editor operations remain compiler-owned. Defaultable parameters participate in function identity and safe assignability, overrides preserve their arity contract, and compiler/LSP labels distinguish omission (`= default`) from nullable input (`?`). Async expressions and block declarations share one resolved-value annotation and native Promise-adoption rule, enforce their own `await` boundary, reject direct `await` in parameter defaults, and fail before Promise values enter JSX. Object-returning arrows are unambiguous, power preserves right association plus predictable unary/await grouping, and strict comparison chains evaluate once while ordered links reject JavaScript bool/object/mixed coercion. Bounded `///` Markdown documents declarations and members across aliases without runtime output or JSDoc types. Multiline imports, parameters, types, constructors, and calls accept final commas without generating indentation tokens. Scope-aware completion, hover, signatures, navigation, visibility, and refactors retain one analyzer/LSP authority. Deterministic malformed inputs are retained across compile, inspect, and format APIs. The retained matrix is recorded in `1.0-acceptance.md`. |
| Web operation and recovery | Passing internally | Web API 0.8 adds bounded application-local `domId` values for accessible label/title/hint relationships without cryptographic UUIDs. Route/callback recovery, explicit dialog focus restoration, namespace-correct accessible SVG JSX across ordinary/lazy component and `foreignObject` boundaries, and IndexedDB commit/retry are owned. HTTP, Web component/navigation props, forms, browser helpers, files, and realtime validate hostile dynamic boundaries before native effects. API Dashboard adds typed HTTP, JavaScript-package interop, a class-owned chart scale whose `init:` rejects invalid construction, responsive SVG passed through a lazy component chunk, and two concurrently loaded typed metric feeds using an async arrow, with three-engine evidence. The official Website separately dogfoods source component packages, native disclosure, modal focus return, form error/hint ownership, and keyboard paths in Chromium, Firefox, and WebKit. Watched rebuild failures retain the last good application, report through the managed development channel, recover on the next edit, and converge after rapid edits. Development and verified CSP production suites pass Chromium, Firefox, and WebKit; broader workload diversity remains correctly owned by the external-use row. |
| Toolchain delivery | Passing internally | Transactional create, strict config/help/LSP transport, packed consumers, reproducible release sets, safe output replacement, exact candidate verification, and independent Workbench hash checks pass. The current packed release passes the Workbench installed-toolchain gate, including exact defaultable/nullable signatures for `domId`, `slice`, and TypeScript-package methods, collection/route signatures, HTML/component/SVG completion, typed object keys, recursive-record rename, semantic tokens, safe equality, class-body fields and `init:`, private-member inside/outside completion, a documented getter delivered as an ordinary read-only property, comparison-chain `bool` hover/inlay hints, declaration documentation in completion/hover, an async arrow's contextual parameter hover and Promise signature, and named-function Promise adoption, plus all 9 focused generic-language-host tests without moving language rules into Workbench. |
| External use and release | Public source passing; runtime evidence still required | Apache-2.0 is applied and retained in all four npm tarballs. Commit `0faf7d5` and draft PR #1 establish attributable public development source; both push and pull-request CI pass on Ubuntu, macOS, Windows, and the browser matrix. The separate Website repository bootstraps from that exact commit rather than local links. A real hosted preview, independent users, compatibility feedback, reviewed merge, stable clean tag, provenance, and explicit publish authority remain absent. |

## Evidence commands

The internal audit must keep these independent boundaries green:

```text
npm run check
npm test
npm run test:packages
npm run test:browser
npm run release:rehearse
npm run release:verify -- release/rehearsal
```

The Workbench evidence is run from its independently packaged generic host
against the packed Velar toolchain. The installed-toolchain gate and all 9
focused language-host tests pass. The wider shared tree still has unrelated
Platform migration links to removed Workspace/System Tools packages; that
baseline is reported separately and Workbench never becomes the compiler or
language authority.

## Claim boundary

Internal completion means the implementation and its reproducible local/CI
evidence are ready for an authorized external preview. It does not mean the
language is already production-ready. That claim additionally requires real
deployment observation, independent application use, compatibility feedback,
and an audited release candidate.

The closed requirement-to-evidence matrix is retained in
[1.0-acceptance.md](1.0-acceptance.md).
