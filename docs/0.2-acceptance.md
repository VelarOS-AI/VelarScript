# VelarScript 0.2 Acceptance Matrix

Status: production hardening and the first reusable Web-library seam are
accepted for the stable-Web-API and application-scale stage.

## Compiler semantic authority

| Contract | Evidence |
| --- | --- |
| One compiler-owned typed symbol/index model | Semantic shadowing/type tests; `CompileResult.semanticIndex` |
| Incremental project sessions recompile changed modules and reverse dependents while reusing unrelated results | `project sessions reuse unaffected modules and invalidate reverse dependencies` |
| Cross-file definition and references include exported declarations and import sites | Project semantic and real LSP protocol tests |
| Rename distinguishes imported names from aliases and rejects invalid, reserved, colliding, field, or unresolved edits | `project semantics resolve imports and keep alias rename fail-closed` |
| Standard LSP definition, references, rename, symbols, signature help, hover, completion, diagnostics, and formatting | `language server publishes diagnostics, hover, and completion` plus semantic requests in the same protocol test |

## Workbench seam

| Contract | Evidence |
| --- | --- |
| Workbench remains a general editor; Velar is an injected built-in contribution | Workbench product-boundary and language-support tests |
| External semantic capabilities use one generic LSP client shared with Python | `routes an injected LSP through generic Workbench semantic contracts` |
| Velar rename failure never falls back to local textual replacement | Semantic-language UI guard and compiler fail-closed rename contract |
| Compiler and editor are independently buildable and neither embeds the other | Package boundaries and independent typecheck/build gates |

## npm Velar source packages

| Contract | Evidence |
| --- | --- |
| `package.json` `velar.entry` publishes one `.vel` source entry through npm | `npm packages publish Velar source through package.json velar.entry` |
| Package source joins analysis, navigation, HMR, and production bundling | Package compilation/build/definition assertions and production example |
| Package-relative imports cannot escape the package root | `Velar source packages cannot escape their package root` |
| No custom package manager, registry, or second declaration/schema language | Resolver and charter contract |

## Browser and production

| Contract | Evidence |
| --- | --- |
| Compile errors overlay the last good app; runtime errors use the same browser surface | Dev-server HTML assertions and browser overlay implementation |
| Runtime frames map back to `.vel` | Dev mapping endpoint test and linked source-map runtime test |
| HMR invalidates relative and npm-distributed Velar modules; module state resets | Revision rewriting assertions for application and package modules |
| Production emits hashed/minified assets and `velar-build.json` with sizes/SHA-256 | `CLI emits complete Web application assets` |
| Production example consumes a reusable Velar source package | `examples/production-web` and `packages/demo-web-kit` check/test/build gate |

## Acceptance commands

```text
VelarScript: npm run check && npm test
Example:     velar check/test/build examples/production-web
Workbench:   bun run check
Packaging:   bun run package:app:dir && bun run verify:app:dir
```

## Next big stage

Velar 0.3 focuses on stable public Web APIs, application-scale performance and
incrementality, automated browser acceptance, production observability, and
broader real-library validation. SSR/server execution, a custom package
registry, complex type-level programming, a custom debug protocol, and
`velar/game` remain deferred.
